# 开发约定

本文保留原开发实践笔记和已结束实施计划中仍有效的工程约束。方法参考李博杰等《AI Agent 实战》；评估方法见[Agent 的评估](../eval/methodology/01-Agent的评估方法论精读.md)。

## 代码与数据边界

- `cmd/` 放程序入口，`internal/` 放 Go 业务模块，`web/` 放客户端，`scripts/data/` 放 Python 数据工具。按实际职责扩展，不预建空架构。
- `internal/rules` 保持零 LLM，使用 depguard 保护；规则决定兼容性，模型不能覆盖判定。
- `internal/schemas` 是 Agent 结构化消息的代码契约，HTTP 契约见 `docs/api/openapi.yaml`，数据库结构以 `db/migrations/` 为准。字段变更同步更新对应设计与契约测试。
- 价格和参数来自可追溯数据库真值；缺失字段输出 unknown，不让模型补造。发布规则见[数据规则](../data/数据获取与发布规则.md)。
- 数据卷保留，普通迁移不执行 `down -v`。本地运行以[运行手册](../ops/本地运行与部署.md)、数据采集与发布以[数据管道设计](数据管道设计.md)为准；项目不使用本机定时任务。

## 模型与执行

- 提示词静态前缀保持稳定；当前需求、版本、预算和锁定件由代码注入，不能让模型翻历史推算状态。
- 工具给出边界、参数和结构化结果，截断必须明确；外部内容作为数据，不能成为指令。
- 生成与校验有明确上限和失败出口；默认 planning，v2/legacy 仅供显式历史诊断，失败不自动回退。
- 固定模型回归同时固定模型版本、参数、用例与快照。额度链评估单独标注；仅修改 `*_MODEL` 不会覆盖非空的 `*_MODEL_CHAIN`。
- 普通启动和离线测试不探测模型；真实调用使用显式检查或 Live 评估。日志不得包含密钥、Cookie、Token 或私人需求全文。
- 记录成功率、重试、Token 和耗时；模型选择不能只比较单次请求价格。

## 检索、状态和交付

- 用户 must 原样传递给模型，不转换成检索前的退出规则。模型自主指定检索条件并可调整查询；规格、报价和兼容性工具只反馈事实。交付前的明确冲突和关键未知保留为方案。embedding 命中不作为核验证据；详见[自主规划流程](自主规划流程.md)。
- 配置修改生成不可变新版本；锁定件、父版本、快照与报价必须对应，验证数据库结果而不只看回复。
- 模型意图与服务端交付状态分开。符合条件的完整方案自动交付，不按 proposal/ready 标签单独裁决；方案、版本关联、回复和运行完成原子保存，同一运行只生成一版。需求修订已变化时保留方案，不覆盖当前配置。
- A2A 保持单跳，跨进程传结构化需求和结果，修复循环留在生成服务内。
- UI、分享、Markdown 和 PNG 复用产品读模型；公开分享只读取可公开字段。

## 修改与验证

- 先定位失败层，再修改提示词、候选、规则或数据；异常分数先检查评估系统本身。
- golden 更新先审阅差异，禁止用更新期望掩盖回归；验证方法见[测试与验收](../eval/测试与验收.md)。
- 文件保留编码、换行和中文说明；`.gitattributes` 规定仓库 LF，避免无关整文件格式变化。
- 文档按功能命名；当前工作只在路线图维护，运行证据进入评估档案，不再复制阶段计划。
