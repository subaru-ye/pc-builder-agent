# P11 本机数据任务

> 状态：实施中。本文只描述已经存在的命令和脚本；外部官方字段适配器尚未启用。2026-08-24 已完成一次真实 PostgreSQL bootstrap 和 weekly/monthly 零变化回灌。

## 1. 当前会做什么

P11 已经具备本机调度和安全发布骨架：

- 校验 `sources.registry.json`、来源权限状态和版本锁。
- 保存 HTTP 原始快照，支持 robots、ETag、Last-Modified、大小限制和访问挑战识别。
- 用确定性代码生成 normalized parts、机器 Diff 和风险分类。
- 低风险变化允许条件发布；高风险变化写入 `scripts/data/work/quarantine/`。
- release 写入 `var/data/releases/`，数据库成功后才切换 `var/data/current.json`。
- 计划任务和模型代码完全隔离，定时运行不会调用百炼、MiMo 或其他模型。

目前唯一启用的可规范化来源是仓库 seed。`amd_products` 仍为 disabled，因此首次安装后的正常结果是“无变化”，不是自动获得新型号。

## 2. 前置条件

- Windows 已安装 Go、uv、Docker Desktop 和 PowerShell。
- 仓库根目录存在未提交的 `.env`，其中 `PG_DSN` 指向本地 PostgreSQL。
- Docker Desktop 已启动。任务会执行 `docker compose up -d postgres redis`，但不能修复未启动或损坏的 Docker daemon。
- 不删除现有数据卷，不执行 `docker compose down -v`。

## 3. 首次初始化

先在可见终端执行：

```powershell
docker compose up -d postgres redis
go run ./cmd/migrate up
uv run --project scripts/data pcdata source check
uv run --project scripts/data pcdata bootstrap
uv run --project scripts/data pcdata health
uv run --project scripts/data pcdata scheduled-run --profile weekly
```

`bootstrap` 会：

1. 严格读取八类 160 个 seed SKU。
2. 生成初始 review 和不可变 release。
3. 调用 Go 导入器，在一个 PostgreSQL 事务中 upsert parts 并记录 publication。
4. 成功后切换 `current.json`；数据库失败时不建立当前指针。

重复执行 `bootstrap` 会返回同一 current release，不重复导入。

## 4. 安装后台任务

确认首次初始化和 weekly 命令正常后执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/data/ops/install-tasks.ps1 -SkipBootstrap
```

不加 `-SkipBootstrap` 时，安装脚本会先启动 Compose 服务、迁移并执行 bootstrap。脚本注册：

| 任务名 | 触发时间 | 实际行为 |
|---|---|---|
| `PCBuilderData-Health` | 每天 03:30 | 检查 current、quarantine 和基础健康状态 |
| `PCBuilderData-Weekly` | 周一 04:00 | 执行 weekly profile |
| `PCBuilderData-Retry` | 周三 04:00 | 执行 retry profile |
| `PCBuilderData-Monthly` | 每天 04:30 唤醒 | 月度幂等键保证每月只实际执行一次 |
| `PCBuilderData-CatchUp` | 用户登录后延迟 5 分钟 | 补最近一次 health/weekly/monthly，不追跑全部历史周期 |

任务使用当前 Windows 用户、隐藏 PowerShell 窗口并拒绝并发实例。它不是 Windows 服务：电脑关机或用户尚未登录时不会运行。

## 5. 如何感知运行结果

任务默认后台运行，不弹出窗口。可以通过以下位置查看：

- Windows“任务计划程序”中的最后运行时间和退出码。
- `var/data/scheduler/logs/`：包装脚本日志。
- `scripts/data/work/runs/<run_id>/manifest.json`：最终状态和安全错误码。
- `scripts/data/work/runs/<run_id>/review.md`：人类可读 Diff。
- `scripts/data/work/quarantine/<run_id>/`：需要处理的高风险变化。
- `var/data/current.json`：当前 last-known-good release。

退出码为 0 表示 `no_change` 或 `published`；非 0 表示 blocked、quarantined 或 failed。日志和 manifest 禁止记录 Key、Cookie、Authorization 和完整模型输入。

## 6. 手动诊断

```powershell
# 默认只做静态检查，不访问网络
uv run --project scripts/data pcdata source check

# 只有明确需要时才对已启用 HTTP 来源执行最小请求
uv run --project scripts/data pcdata source check --live

uv run --project scripts/data pcdata health
uv run --project scripts/data pcdata scheduled-run --profile weekly
uv run --project scripts/data pcdata scheduled-run --profile weekly --catch-up
```

不要通过修改 registry 把未核验来源直接设为 enabled。启用前必须具备条款/robots 结论、确定性解析器、身份匹配规则和 fake HTTP 测试。

## 7. 卸载

```powershell
powershell -ExecutionPolicy Bypass -File scripts/data/ops/uninstall-tasks.ps1
```

卸载只移除五个 `PCBuilderData-*` 任务，不删除 PostgreSQL/Redis 数据卷、run、quarantine 或 release。需要清理本机运行数据时应另行备份和确认目标，本脚本不自动删除。
