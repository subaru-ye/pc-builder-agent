# 装机配置单 Agent — 技术选型(ADR)

> 2026-07-26 · 技术栈决策记录,语言/框架/模型供应商以本文为准
> 当前架构见[系统架构](系统架构.md)；实际依赖版本以 `go.mod`、Web 锁文件及数据项目锁文件为准。

## ADR-001 后端语言与 Agent 框架:Go + ADK-Go

- **状态**:已定(2026-07-26)
- **候选**:Go + ADK-Go / Python + ADK / TypeScript + Pi([earendil-works/pi](https://github.com/earendil-works/pi))
- **决策**:Go + [google.golang.org/adk](https://github.com/google/adk-go)(ADK-Go,已发 2.0,含 workflow/loop 编排原语与内置 dev UI launcher)
- **理由**:后端语言意向是 Go;ADK-Go 让 Go 意向、主流框架 ADK 经验、A2A 学习目标、免费调试 UI 四者兼得。Pi 出局:TypeScript 绑定与 Go 冲突,且其设计立场是刻意不做多 Agent 编排与 A2A;Python 出局:与语言意向不合(它是 ADK 旗舰版本,文档最全,作为查资料的对照版本继续存在)。
- **代价与对策**:社区教程/示例多为 Python 版 → 遇问题对照 Python 文档翻译成 Go API,优先看 pkg.go.dev 与 adk-go 仓库示例;LiteLLM 是 Python 独有 → 见 ADR-004。

## ADR-002 A2A:官方 a2a-go SDK

- **决策**:单跳服务拆分使用 [a2aproject/a2a-go](https://github.com/a2aproject)。
- 消息 schema 的 Go struct 定义于 `internal/schemas`,与系统架构 §四对齐;字段变更回写设计方案,不在代码里静默漂移。

## ADR-003 数据层:PostgreSQL 16 + pgvector、Redis 7(沿用,不重开选型)

- 记忆基座(PG/pgvector/Redis)是学习目标本身,语言切换不影响。
- 访问层:pgx + pgvector-go + go-redis。不引入重 ORM;如需类型安全查询生成仅在实际需要时补充类型安全查询生成。

## ADR-004 模型接入

- 三个角色使用统一 `modelprovider`，可独立指定供应商、端点、Key 和模型；角色 Key 优先于供应商 Key。
- 当前配置示例：Builder `qwen3.8-max-0902`，Screening `deepseek-v4-flash-0731`，Embedding `qwen3.7-text-embedding`；均通过百炼，chat 切换链清空。
- 固定模型回归与额度链模式分开记录。模型支持范围、Responses 协议和失败策略见[供应商适配决策](ADR-007-模型供应商适配与成本控制.md)。

## ADR-005 数据管道:Python 3.12 + uv

- **决策**:数据导入/embedding 生成/性能分脚本用 Python,与 Go 服务端并存,边界 = `scripts/` 目录。
- **理由**:dbgpu 是 pip 包、passmark-scraper 是现成 Python 脚本;一次性/低频运行的工具,用 Go 重写纯属浪费。

## ADR-006 客户端:Next.js + React

- **调试入口**:ADK-Go 内置 launcher 的 Web UI(嵌入 host 二进制)+ CLI 脚本,零自研前端。
- **产品入口**(2026-07-26 已定):Next.js + React。理由:生态最大、chat 流式交互组件成熟;SSR 直接解决公开链接分享页的 OG 预览与首屏渲染(PRD FR-603);与设计方案 §七原候选一致。
- **客户端工程栈**(2026-08-09 已定):App Router + TypeScript strict + Tailwind CSS + shadcn/ui(Radix 基础);TanStack Query 管服务端状态,Zustand 只管移动面板/diff 选择等瞬时 UI。前端放 web/,用 pnpm 锁依赖。
- **传输边界**:浏览器只调用 Go 的 /api/v1 产品契约;长任务以后台 run + SSE 交付,不直接依赖 ADK REST/Event。Next.js 只承担渲染、同源 rewrite 和 ImageResponse 分享图,不用 API Routes/Server Actions 写业务逻辑,避免出现双后端。
- **渲染边界**:分享页用 Server Component;聊天、需求表单和 SSE 使用局部 Client Component,不把整棵应用无差别标成 use client。

## ADR-008 账号:独立 Supabase Auth + Go BFF

- **决策**:本地可选账号使用固定 `supabase/gotrue:v2.196.0`；浏览器只持有 Go API 签发的 HttpOnly opaque Cookie，Supabase Token 加密存 Redis。
- **所有权**:账号关联一个或多个匿名 owner，不改写历史会话，保持 Agent context 与分享 token 稳定。
- **范围**:邮箱密码、资料、改密和退出；本地自动确认邮箱。公网 SMTP、找回密码、OAuth、MFA 与角色权限延期。
- **完整论证**:见 [ADR-008](ADR-008-Supabase-Auth账号系统.md)。
