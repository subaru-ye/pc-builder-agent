# 评估工作台按对象、资产与验证分区

原工作台把所有运行放在长列表中，评估集、提示词和结果混在运行详情里，难以独立观察迭代。`/eval` 现在默认进入 Screening 工作区，左侧导航分为评估对象（Screening、Builder）、迭代资产（评估集与题目、提示词迭代）、验证（测试记录、运行对比）。沿用现有主题和组件，不增加依赖。

- Screening 与 Builder 按测试目的组织实验与所选结果，不截断为最近八条；不合并模型层与确定性层分数。Go 运行摘要新增 `layer_scores`，直接投影冻结报告，不从摘要文字反解析。
- 评估集默认直接浏览完整题库，分「题目 / 迭代记录 / 关联测试」三个页签。题目按 Screening、Builder 与分类筛选，每页 12 条，搜索场景、输入或题号；展开查看用户输入、逐轮期望及设计依据。题库含本次未测试的用途分组，输入和期望由所选版本的运行内文件提供，哈希不一致时不展示。
- 提示词默认按角色展示当前静态原文，主提示词、格式纠偏及 Builder 各次尝试输出契约分别阅读。原文取自本机 evaldesk 服务的编译常量，内容指纹复用既有提示词证据规则，修改源码需重启服务更新；不代表历史运行使用的版本。历史测试独立成页签，展示代码身份、dirty 状态、模型配置及关联测试；这批历史产物未保存原文，不能据哈希还原文本或据代码提交判断提示词差异。
- 测试记录增加冻结门槛筛选与每页 12 条的分页；证据状态仍与门槛状态独立。归档默认折叠。
- 运行详情拆成结果概览、门槛检查、评估集与题目、模型与提示词、运行证据五区；结果默认显示失败且未跳过的题目。选择对比时预填基线，未选候选时显示选择提示，不显示虚假加载状态。
- `area` / `panel` 与既有 `run` / `case` / `layer` / `va` / `vb` 参数承载深链接，支持刷新及浏览器前进后退；旧 `view=compare` 和 `run` 深链保留。

边界：仍是本机 GET-only 只读工作台，不启动模型评估、不改题目或提示词。Builder 仅覆盖 Requirement v2 的 policy/ui-contract，planning-v2 输出质量尚未接入。旧 legacy 桌维持移除状态。

验证覆盖 Go 目录分层投影、前端类型与 lint、Vitest、Playwright 合成产物及真实运行抽查，包含六区导航、分页/筛选、冻结题目、对比空态、深链接与返回、1440/768/375 视口、亮暗主题和 axe 严重等级检查。

后续修复：旧本机服务的运行摘要缺少 `layer_scores` 时，客户端从既有详情 `per_layer` 补齐当前运行的冻结分数（最多四个并发请求，归档不补读），避免把未知误判为两侧零运行。补读失败显示读取错误，可重试，不伪造零分。导航、空态与通用错误中的内部版本名称已移除；冻结证据本身的版本身份保留。

评估集迭代改版：主界面围绕题目，历史日期收进「题目版本」选择器与迭代页。版本仍按完整 manifest 哈希归组，日期表示首次使用，不虚构人工版本号或修改原因。`snapshot` 保存版本选择，`dataset_view` / `dataset_side` / `dataset_layer` / `dataset_page` / `question` 保存页签、对象、分类、分页及展开题目；刷新与前进后退恢复选择。归档范围用 `dataset_archived` 保存。

新增 GET `/api/evaldesk/requirement-v2/dataset?id=<run>`，复用逐题证据的文件校验与投影，返回全部题目、每题内容指纹和读取缺口。逐题指纹在截断前按规范 JSON 生成，格式变化不算修改。迭代页对相邻使用记录显示新增、修改、移除的题目，修改可展开前后内容和变更字段；任一侧有校验缺口时不生成增删结论。分类与评分规则变化收进二级详情，不据此声称效果改善或继承关系。

覆盖图与会话用途分组收进「题库分组与评分信息」；删除长用途说明、辅助文件说明和重复标识入口。技术指纹仅在版本核对或文件校验详情中显示。运行内评估集页保留完整覆盖图，并在折叠分组信息中标注未使用的用途分组，逐题索引仍只列本运行涉及的题目。此改版需要启动更新后的本机 evaldesk 服务。

题目阅读布局：列表按分类分组，分类标题附测试范围说明；原「分类 · 开发回归」后缀改为独立「用途：回归测试」，展开后明确分类与用途含义。桌面并排对照用户输入与预期结果，窄屏上下排列；预算等字段的值、状态、强度合成紧凑行，需求操作以操作/字段/值展示。来源、设计依据、原始状态及未映射的判分条件保留在折叠详情，不将嵌套 JSON 全部摊开。

新增 GET `/api/evaldesk/requirement-v2/prompts`，只返回当前编译的 Screening 需求增量协议与 Builder 静态原文及 SHA256，不读取环境配置、日志或动态请求，也不回填历史产物。`prompt_role` / `prompt_view` / `prompt_component` 保存角色、视图与组成部分。历史运行详情纠正为“仅记录逐请求哈希”，不再暗示 events.jsonl 包含原文。`cmd/eval` 的 prompts.json 冻结机制属于另一评估入口，此工作台的历史 `cmd/evalrequirement` 产物没有该文件。

提示词版本迭代：新增 GET `/api/evaldesk/requirement-v2/prompt-versions`，从固定的 Screening / Builder 源码路径读取最近 80 个 Git 文件提交，使用 Go AST 提取字符串常量原文、按内容指纹合并重复内容，并保留首次出现的提交信息；不执行历史源码，不把普通代码改动当作提示词修改。旧 Builder 只还原静态主提示词，不执行历史函数来重建输出契约。页面提供版本选择、原文与增删对比，`prompt_version` / `prompt_base` 保存选择，缺失组成部分不视为新增或移除。

后续 `cmd/evalrequirement -mode live` 在第一次模型请求前创建 `prompts.json` 并在 plan 写入静态提示词身份；保存失败即停止，禁止覆盖已有文件。工作台只展示与声明指纹完全一致的运行原文，同内容的多次测试合并为一个版本并提供关联测试入口。运行摘要的完整性状态纳入提示词原文校验，文件变化会使缓存失效；Git 历史与实际测试保存的原文明确区分。历史评估产物保持原样，未重跑模型。

本机服务更新：Next 开发热更新不会重编译 `cmd/evaldesk`。接口变更后必须更新并重启 `EVALDESK_API_BASE_URL` 实际指向的服务，默认工作台是 3101 → 8086；另开的验证服务不替代常用入口。版本接口返回 404 时明确提示服务版本需要更新，不再以“读取失败”掩盖原因；失败时停止显示加载中，服务恢复后可重新读取。已在 3101 入口验证历史版本与内容对比。

提示词阅读与差异（2026-10-08）：长原文默认按已有空行段落阅读，提供段落导航、段落字符数与完整原文入口，阅读标签不写回提示词。`prompt_read=full` / `prompt_section` 保存阅读方式与段落，刷新恢复。对比先按行定位变化区间，再用有界 Myers 字符差异标记区间内真正增删的内容；中文与 emoji 按 Unicode 码点计数，换行计入字符数。默认折叠未改动区间与长上下文，前后并排、窄屏上下排列，显示增删字符数、变化区间数量及两版长度。自动对照按展示时间选择更早的不同内容版本，不暗示继承关系，也可手选。每侧超过 400 行时直接全文字符对比；字符搜索超过 50 万个位置时保留公共首尾、展示中间替换区间，明确提示这部分未细化，不声称字符数是最小编辑量。
