本轮确定缺陷修复：

## 数据缺口与处置

- 当前 active 商品缺价 **0**。买手观察日期保持原值，发布日不等于当日重新报价，更不代表库存；右侧不再显示“价格过久”，仍显示快照日期、参考价和真实缺价。
- **11 件兼容性规格有缺口**：10 款散热器缺 `cooling_capacity_w`，Gigabyte B650 AORUS ELITE AX 缺 `memory_speed_max_mts`，逐件见 `coverage.json`。不推算散热瓦数；可改选已知规格候选，或有已读正文证据后仅补入当前会话。
- ITX 的电源形态/尺寸尚未进入当前全局 schema，12 条规则通过不能证明电源能装进机箱。C123-005 由 oracle 主动保留该问题，**不代表自动规则已经检测此缺口**；本轮不扩建采集或规则体系。
- 当前库整机价格必要下界：有独显 5627.50 元、带已知核显且无独显 3476.50 元；忽略兼容关系的下界已超过 3000 元，因此当前快照无法提供 3000 元完整办公整机。这个结论不适用于整个市场。已有可选 3975.12 元办公方案。
- 静音、游戏 FPS、生产力耗时缺实测覆盖，不能作保证。缺证据的记录暂缓；不要求所有候选入库。

## 使用与复现

普通用户继续在 `http://localhost:3000` 描述需求，已有配置可直接说“换 CPU”“预算改为……”；待解决方案可以补充信息或换备选后继续。历史版本页只读，保留原报价。

```bash
# 默认：当前123件的10个机制场景，零真实模型调用
python scripts/eval/planning/run.py --out artifacts/current123-new

# 指定历史固定目录回归；默认入口变更不覆盖历史资产
python scripts/eval/planning/run.py --suite internal/planningeval/testdata/proposal-review-20260915/suite.json --out artifacts/historical-new

# 重放本次真实CPU回答，不再次调用模型
python scripts/eval/planning/run.py --suite internal/planningeval/testdata/current-123-20260915-r2/cpu-recorded/suite.json --out artifacts/cpu-replay-new
```

运行需要已有 Go/Python/Docker。输出目录必须不存在。默认创建专用 PostgreSQL 容器；遇本机随机端口问题，可显式设置 `PLANNING_EVAL_ADMIN_DSN` 为本机管理员连接并传 `--local-postgres`，仅在既有 `pc-builder-agent-postgres-1` 创建和清理本次随机 `peval_` 数据库，业务库不作为测试库。`--go-tests` 可配 `--test-run` 复用指定测试。连接密码不写入报告或命令示例。

本目标真实调用额度已用完，以上复现命令均为离线；不要再次执行 live。常驻服务加载信息记录在 `var/run/current-123-20260915/processes.json`，具体健康检查以交付时结果为准。
