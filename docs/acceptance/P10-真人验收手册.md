# P10 真人盲评手册

> 用途:阶段 1 封板的最终人工门禁。本手册不允许开发者代替真实受试者评分。

## 1. 样本与隐私

固定邀请 3 位未参与开发的受试者:

- R1:`novice`,装机新手。
- R2:`hardware_familiar`,了解硬件但不熟悉本项目。
- R3:`builder_experienced`,有实际配单经验。

只记录 R1/R2/R3、类型、评分、是否发生主持人协助、匿名卡点与转述摘要。不记录姓名、联系方式、Cookie、分享 token、完整私人需求或屏幕录像。

## 2. 主持人准备

1. 确认 PostgreSQL、Redis、buildsvc、API 和 Web 健康,API `/readyz` 不得 degraded。
2. 确认百炼免费额度和防扣费开关,不配置付费回落模型。
3. 每位受试者使用全新无痕浏览器上下文,从首页开始。
4. 只对受试者说:「请用这个工具为自己或一个假想用户生成并修改一份装机配置。」
5. 不解释界面、校验语义和按钮位置。只有受试者明确表示无法继续时才能提供最小协助,并记录 `assisted=true` 及卡点。

## 3. 受试任务

受试者必须独立完成:

1. 输入预算、用途和至少一项偏好。
2. 阅读需求卡,至少修改一个字段后确认。
3. 阅读生成的八类配件、总价、快照日期和 12 条校验。
4. 指出三条免责中至少一条对购买决策的影响。
5. 降低预算或修改一项硬件偏好,生成新版本。
6. 找出两个版本变化的品类与金额。
7. 创建分享,打开只读页并下载 Markdown 或 PNG。
8. 回答:「你是否会直接按这份配置作为购买前参考?」

## 4. 评分口径

每项只能取 0/1/2:

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| requirement_fit | 明显误解 | 部分正确,需修改 | 准确一致 |
| completeness | 缺关键件 | 完整但有疑问 | 完整清楚 |
| trust | 看不懂结论 | 只理解部分 | 校验、快照和免责清楚 |
| change_control | 非目标件乱变 | 有少量不合理变化 | 变化符合意图 |
| direct_buy | 不可用 | 修改后可用 | 可直接作为购买前参考 |
| share_clarity | 关键信息缺失 | 基本可读 | 脱离聊天仍可独立理解 |

3 人样本下,`direct_buy` 达到 80% 等价于 3/3 全部得 2 分。其他维度的平均分作为诊断信息,不能抵消 direct_buy 失败。

## 5. 结果文件与校验

复制 `human-results.template.json` 到 `artifacts/p10/human-results.json`,用真实评分替换全部 `-1`。原始文件不入库;全部通过后才把同一份脱敏结果复制为阶段验收证据。

```powershell
go run ./cmd/p10report `
  -final `
  -live artifacts/p10/<run>/live-results.json `
  -human artifacts/p10/human-results.json
```

如果评分后修改了产品,这三份盲评立即失效;最终封板需使用未见过旧版界面的新样本重新评分。
