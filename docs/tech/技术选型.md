# 装机配置单 Agent — 技术选型(ADR)

> 2026-07-26 · 技术栈与关键决策记录,语言/框架/模型供应商/账号以本文为准
> 当前架构见[系统架构](系统架构.md)；实际依赖版本以 `go.mod`、Web 锁文件及数据项目锁文件为准。

## ADR-001 后端语言与 Agent 框架:Go + ADK-Go

- **状态**:已定(2026-07-26)
- **候选**:Go + ADK-Go / Python + ADK / TypeScript + Pi([earendil-works/pi](https://github.com/earendil-works/pi))
- **决策**:Go + [google.golang.org/adk](https://github.com/google/adk-go)(ADK-Go,含 workflow/loop 编排原语与内置 dev UI launcher)
- **理由**:后端语言意向是 Go;ADK-Go 让 Go 意向、主流框架 ADK 经验、A2A 学习目标、免费调试 UI 四者兼得。Pi 出局:TypeScript 绑定与 Go 冲突,且刻意不做多 Agent 编排与 A2A;Python 出局:与语言意向不合(作为 ADK 旗舰文档对照保留)。
- **代价**:社区教程多为 Python 版 → 对照 Python 文档翻译成 Go API,优先看 pkg.go.dev 与 adk-go 仓库示例。

## ADR-002 A2A:官方 a2a-go SDK

- **决策**:单跳服务拆分使用 [a2aproject/a2a-go](https://github.com/a2aproject)。
- 消息 schema 的 Go struct 定义于 `internal/schemas`;字段变更回写设计文档,不在代码里静默漂移。边界见[服务与状态](服务与状态.md)。

## ADR-003 数据层:PostgreSQL 16 + pgvector、Redis 7(沿用,不重开选型)

- 记忆基座(PG/pgvector/Redis)是学习目标本身,语言切换不影响。
- 访问层:pgx + go-redis,向量用文本字面量 `'[…]'::vector`(160 SKU 量级不引入 pgvector-go)。不引入重 ORM。

## ADR-004 模型接入

- 三个角色使用统一 `modelprovider`,可独立指定供应商、端点、Key 和模型;角色 Key 优先于供应商 Key。
- 当前配置:Builder `qwen3.8-max-0902`,Screening `deepseek-v4-flash-0731`,Embedding `qwen3.7-text-embedding`;均通过百炼,chat 切换链清空。详见 ADR-007。

## ADR-005 数据管道:Python 3.12 + uv

- **决策**:数据导入/embedding 生成/性能分脚本用 Python,与 Go 服务端并存,边界 = `scripts/` 目录。
- **理由**:dbgpu 是 pip 包、passmark-scraper 是现成 Python 脚本;一次性/低频运行的工具,用 Go 重写纯属浪费。

## ADR-006 客户端:Next.js + React

- **调试入口**:ADK-Go 内置 launcher 的 Web UI + CLI 脚本,零自研前端。
- **产品入口**:Next.js + React。生态最大、chat 流式交互组件成熟;SSR 直接解决分享页 OG 预览与首屏渲染。
- **工程栈**:App Router + TypeScript strict + Tailwind CSS + shadcn/ui(Radix 基础);TanStack Query 管服务端状态,Zustand 只管瞬时 UI。前端放 `web/`,用 pnpm 锁依赖。
- **传输边界**:浏览器只调用 Go 的 /api/v1 产品契约;长任务以后台 run + SSE 交付。Next.js 只承担渲染、同源 rewrite 和 ImageResponse 分享图,不用 API Routes/Server Actions 写业务逻辑。
- **渲染边界**:分享页用 Server Component;聊天、需求表单和 SSE 使用局部 Client Component。

## ADR-007 模型供应商适配与成本控制

> 状态:已接受并实现(2026-08-12)。

### 决策

统一使用 `internal/modelprovider` 装配三个独立角色:

| 角色 | 当前供应商 / 模型 | 默认思考 | 说明 |
|---|---|---|---|
| screening | bailian / `deepseek-v4-flash-0731` | none | 产品 API 使用无 ADK 历史回灌 Agent |
| builder | bailian / `qwen3.8-max-0902` | none | 固定评估配置,保持 none |
| embedding | bailian / `qwen3.7-text-embedding` | 不适用 | 当前固定 1024 维 |

- 支持 `bailian`、`mimo` 和 `openai_compatible`。通用兼容端点必须实现 OpenAI Responses `/responses`。MiMo 暂不支持 embedding;MiMo builder 暂只允许 `reasoning.effort=none`(思考模式的多轮工具调用需完整回传 reasoning history,当前 ADK 适配无法保证无损保留)。
- 配置优先级:角色专用配置 > 供应商配置 > 百炼旧变量。服务启动只做静态校验,不探测或消费额度;联网验证显式执行 `go run ./cmd/modelcheck -role <role>`。
- 固定模式遇错误明确失败;只有显式非空 `*_MODEL_CHAIN` 才允许链内按既有错误策略切换,不跨供应商或链外回退。链非空时优先于 `*_MODEL`,固定回归应清空。SDK 自动重试默认 0,防止响应丢失后重复计费。
- `qwen3.8-max-0902` 的 `reasoning.effort=low` 返回 400 `InvalidParameter`,该 Model Code 在配置层静态例外为 `none`;其他百炼 builder 未显式配置时仍默认 low。

### 成本与延迟约束

- 产品初筛只读取数据库中同类 screening/change run 的最近 6 条稳定消息,总长度最多 4000 Unicode 字符;build 交付、工具事件和 A2A 内部事件不得进入。
- “换成 A 卡/AMD 显卡”与“换成 N 卡/NVIDIA 显卡”等无歧义表达走纯规则 ChangeRequest 并锁定其余七类;否定、含糊或具体型号继续交给模型。
- 检索工具常规 `top_n=5`,允许 1..8;越界显式报错。提示模型同一响应并行发出多个无依赖 function call,并禁止已有足够候选后重复同条件检索;实际并行程度取决于供应商。
- embedding Redis key 同时包含 provider、端点 host、model 和 dimension 的摘要,避免跨供应商误命中。
- 只有设置 `P10_METRICS_DIR` 时才写脱敏指标(provider、role、model、Token 分类、耗时、cache、安全错误类别),不记录正文、Cookie、token 或 Key。

### 配置示例

```dotenv
SCREENING_PROVIDER=bailian
SCREENING_MODEL=deepseek-v4-flash-0731
SCREENING_MODEL_CHAIN=
SCREENING_REASONING_EFFORT=none

BUILDER_PROVIDER=bailian
BUILDER_MODEL=qwen3.8-max-0902
BUILDER_MODEL_CHAIN=
BUILDER_REASONING_EFFORT=none

EMBEDDING_PROVIDER=bailian
EMBEDDING_MODEL=qwen3.7-text-embedding

MODEL_MAX_RETRIES=0
```

角色可用 `SCREENING_API_KEY/BASE_URL` 等覆盖供应商配置。MiMo 与通用端点没有隐式模型默认值,必须填写精确 Model Code。账户余额与免费额度由供应商控制台人工确认,本项目不查询计费账户。

## ADR-008 账号:独立 Supabase Auth + Go BFF

> 状态:已采用(2026-08-30)。适用于本地学习环境;尚不满足公网开放注册条件。

- 账号服务采用独立 `supabase/gotrue:v2.196.0`,只复用 PostgreSQL 的 `auth` schema,不安装完整 Supabase 平台。浏览器与 Next.js 不直接访问 GoTrue,也不持有 Token;Go 产品 API 作为 BFF,通过随机 `pcb_auth_session` HttpOnly Cookie 标识登录会话,Token 以 AES-256-GCM 加密后存入 Redis。
- 首版仅支持邮箱密码注册、登录、显示名称、修改密码和退出;邮箱自动确认,只用于本地学习。公网开放前必须增加真实 SMTP 与邮箱验证、CAPTCHA、限流、HTTPS、密钥轮换和账号恢复流程。
- **身份与数据归属**:匿名模式继续可完整使用(`pcb_anonymous_id`);`product_user_owners` 把一个账号关联到多个历史匿名 owner;登录自动认领当前 owner 但不改写 `web_sessions.owner_id`,Agent contextID、版本树、分享 token 和幂等语义保持不变。已认领 owner 不再允许匿名 Cookie 访问;退出时删除认证 Cookie 并旋转匿名 Cookie。登录身份可访问其全部关联 owner 的会话、run、build、导出和分享管理;其他账号统一 404。
- **Token 与错误策略**:`AUTH_SESSION_SECRET` 必须为独立 32 字节 base64url 密钥;Token 保险箱 TTL 30 天,Access Token 临近过期时以 Redis 锁串行刷新。Auth Redis 故障时登录返回 `auth_unavailable`,不静默降级为访客。Auth 写请求使用 UUID 幂等键;上游响应正文、邮箱、密码和 Token 不进入日志或 Problem detail。
- 本地初始化与操作步骤见[Supabase-Auth 本地账号系统](../ops/Supabase-Auth本地账号系统.md)。
