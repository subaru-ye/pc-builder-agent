# 流水线与工具调用

> 本文维护 legacy 工具调用路径和各 Agent 的职责。默认选配使用[Harness v2](Agent-Harness-2.0.md)，由程序准备候选，Builder 不声明工具。legacy 仅在 `BUILD_HARNESS_MODE=legacy` 时显式启用，不是失败回退。

## 1. 职责

初筛把用户文本变为 RequirementSpec 或 ChangeRequest，缺失信息时追问；生成节点在候选中选件；校验节点执行规则、报价与交付判定。初筛不参与生成修复循环，状态与预算由程序计算。

## 2. 编排

生成服务包含 ingest、改单预处理和生成校验路径。legacy 使用 ADK Loop(builder → validator)，默认 v2 使用自定义 Harness。A2A 在初筛消费方与生成服务之间保持单跳，见[A2A 服务边界](A2A服务边界.md)。

## 3. 提示词与上下文

提示词在 `internal/agents/pipeline/prompts.go` 与 Harness 中维护。静态前缀保持稳定，需求、基版本、锁定件和校验反馈作为动态输入。不得根据静音、颜值等软偏好推断品牌硬约束；schema 错误必须反馈后重试，不能仅重复相同请求。

## 4. 工具契约

- `search_parts`：接收结构化硬约束，从零件库过滤候选。参数边界、SKU 与返回字段见[实现](../../internal/agents/tools/searchparts.go)；截断必须明确。
- `search_parts_semantic`：服务静音、颜色、风格等软偏好，返回可解释候选。硬约束仍由确定性过滤处理，见[语义选件](语义选件.md)及[实现](../../internal/agents/tools/searchsemantic.go)。
- `validate_build` 工具封装保留在代码中，但当前 Builder 不持有该自检工具，避免重复校验。最终判定始终来自生成循环内的确定性 validator。
- legacy 检索提示允许同轮发出独立工具调用；实际并行取决于模型。默认 v2 不依赖这项模型能力。

## 5. 停止与错误

校验成功、重试耗尽或不可恢复错误会终止当前生成。失败不能保存为成功版本；unknown 不能冒充 pass。详细预算、锁定与修复策略见[Harness](Agent-Harness-2.0.md)。

## 6. 状态与持久化

需求、基版本、预算、锁定清单和历史修改由程序维护。Redis 的会话状态与 PostgreSQL 的不可变业务版本职责不同，见[版本与改单](版本快照与增量改单.md)、[会话与缓存](Redis会话与缓存.md)。

## 7. 模块边界

`internal/agents/pipeline` 装配流程，`internal/agents/tools` 封装工具，`internal/buildharness` 实现默认选配，`internal/rules` 保持零 LLM。结构化字段以 `internal/schemas` 为准。

## 8. 验证

离线校验工具参数、错误分类和契约；显式 Live 测试确认跨服务交付与恢复。提示词修改跑固定模型评估，不能仅以单条冒烟用例替代回归。见[测试与验收](../eval/测试与验收.md)。
