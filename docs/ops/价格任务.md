# 价格任务

> 人工 CSV、review/publish 和价格健康检查可用；自动价格来源未达到激活门槛，来源和每日任务保持禁用。

## 1. 初始化

保留数据卷启动服务并迁移：

```powershell
docker compose up -d postgres redis
go run ./cmd/migrate up
uv run --project scripts/data pcdata price health
```

首次迁移会把历史价格标记为 `bootstrap/legacy`。此时 health 很可能是 `stale`，这表示系统诚实识别了旧价，不是基础设施故障。

## 2. 人工价格 CSV

固定表头：

```text
sku,price_cny,currency,source_id,product_id,source_url,seller,price_type,stock_status,variant_match,observed_at,raw_sha256
```

不要把搜索摘要、大模型回答、购物车截图中的模糊总价或历史 `jd/zol` 标签填成证据。`source_url` 必须定位到人工核验的具体商品，`raw_sha256` 对应当时核验内容。

分三步运行，review 与 publish 分离：

```powershell
uv run --project scripts/data pcdata price import --file C:\safe-input\prices.csv --run-id 11111111-1111-4111-8111-111111111111
uv run --project scripts/data pcdata price review --run-id 11111111-1111-4111-8111-111111111111
uv run --project scripts/data pcdata price publish --run-id 11111111-1111-4111-8111-111111111111 --policy manual
uv run --project scripts/data pcdata price health
```

发布前检查 `scripts/data/work/price-runs/<run_id>/review.json`：

- `publish`：存在安全新价或真实新观察日期。
- `no_change`：不会创建快照。
- `quarantine`：达到批次异常阈值，禁止发布。
- `quarantined` 列表：单 SKU 超过 25%，该 SKU 会沿用上一正式值。

## 3. 后台 inbox

Windows weekly/retry 会扫描：

```text
var/data/price-inbox/*.csv
```

文件成功处理后改名为 `.processed`；失败文件保留，规格发布不回滚，run 标为 `partial`。放入 inbox 前仍应在可见终端运行一次 import/review。正式任务继续由 `scripts/data/ops/run-scheduled.ps1` 启动，使用 Compose service 名检查 PostgreSQL/Redis。

## 4. 输出与排障

| 路径 | 内容 |
|---|---|
| `scripts/data/work/price-runs/<run_id>/` | import、observations、selection 和 review |
| `var/data/price-releases/<release_id>/` | 不可变价格 release |
| `var/data/current-price.json` | 当前价格 last-known-good 指针 |
| `var/data/scheduler/logs/` | 后台任务日志 |

常见错误：

- `invalid_price_csv`：表头、枚举、金额、时间、URL、哈希或 active_core 校验失败。
- `price_quarantined`：批次异常数量达到门槛。
- `price_database_import_failed`：数据库原子导入失败；current-price 不切换。
- `current_price_corrupt`：指针或 release 哈希不一致，应停止发布并检查本机文件。

## 5. 自动来源状态

- `manual_price_csv`：启用，仅作人工导入和故障恢复。
- `zol_price_candidate`：禁用，`permission_required`；不得通过改 registry 绕过许可门禁。
- `serpapi_baidu`：禁用；2026-08-27 真实 canary 为 0/12 购物结果，未达到激活门槛。
- 京东联盟：不属于实施来源。

SerpApi Key 只写入未跟踪 `.env`：

```dotenv
SERPAPI_API_KEY=你的Key
SERPAPI_BASE_URL=https://serpapi.com
SERPAPI_MONTHLY_REQUEST_BUDGET=240
SERPAPI_DAILY_SKUS=7
SERPAPI_REQUIRE_FREE_PLAN=true
```

真实 canary 会先免费读取 Account API，再精确执行 12 次查询；不会发布价格。2026-08-27 已执行一次且未达标，不应在没有修改来源策略或适配器的情况下反复消耗额度：

```powershell
uv run --project scripts/data pcdata price collect --mode canary
```

检查 `scripts/data/work/price-runs/<run_id>/serpapi-report.json` 和脱敏后的 observations。只有 `shopping_result_skus >= 10`、`dual_match_skus >= 9` 且人工确认零误匹配后，才在独立提交中完成三项激活：

1. 把 `serpapi-baidu-products.json` 的 `activation_status` 改为 `active`。
2. 把 registry 的 `serpapi_baidu.enabled` 改为 `true`，并将固定 96 个 SKU 保持 `active_core`、其他 64 个改为 `catalog_only`。
3. 重新运行 `install-tasks.ps1 -SkipBootstrap`，安装每日 03:45 的 `PCBuilderData-PriceDaily`。

本次真实结果和 Bing/Google Shopping 候选诊断见[SerpApi 价格来源实测](../data/数据来源决策.md)。在新来源通过同等门禁前继续使用人工 CSV 和 last-known-good，不得解析普通搜索结果或 AI 摘要冒充报价。

96 个 SKU 的最终查询词和身份 token 已固化在 `serpapi-baidu-products.json`。目录型号确需调整时，显式运行 `uv run --project scripts/data python scripts/data/tools/generate_serpapi_mapping.py`，逐项审查 diff 后才能提交；定时任务不会自行重写映射。

激活前安装脚本只保留原五项任务，CatchUp 也不会消费 SerpApi 额度。每日任务每次最多 7 次搜索；非 Free、额度不可读、预计超过 240 次、401/403/429 都会失败关闭并沿用旧价。原始 API JSON 只在忽略目录保留 7 天，日志和 release 不保存 Key 或完整响应。

常见 SerpApi 错误：

- `serpapi_key_missing`：`.env` 未配置 Key。
- `serpapi_not_free_plan`：账户不是 Free，拒绝运行。
- `serpapi_budget_exhausted`：账户剩余额度不足或会越过项目 240 次硬限制。
- `serpapi_not_activated`：canary 尚未人工批准。
- `serpapi_authentication` / `serpapi_rate_limit`：鉴权或限流失败，不自动换来源。
