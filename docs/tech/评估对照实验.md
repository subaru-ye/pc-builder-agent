# 评估对照实验

本文约定多轮基线完成后的实验顺序和判定方式。v1.5 固定模型基线已完成 150/150、Pass^3=50/50；修复环对照已完成，关闭语义检索组正在运行，模型与解释质量尚待完成。真实结果和限制见[运行记录](../eval/运行记录.md)。

评估入口支持 `-attempt-limit 1`（默认 3）和 `-semantic=false`（默认 true）；实际值写入 meta 的 `harness_profile`。`cmd/evalcompare -a <目录A> -b <目录B> -factor repair -out <新目录>` 零模型读取两轮产物，复验判卷并要求同清单、同快照、同二进制、至少三次重复和唯一变量变化。factor 也支持 semantic/builder/screening；报告包含逐题胜负和按题目聚类的 bootstrap 区间，原记录不会被覆盖。尚无真实数据时不能将开关实现或单元测试当作机制有效的实验证据。

对照复验完整产物，包括多轮实际上下文；repair/semantic/builder 仅以 build 阶段计算效果，screening 仅以初筛和多轮阶段计算效果。其他阶段的题号明确列为排除项，不能把无关阶段的随机分差算作变量收益。可用同一 v1.5 全集完成所有实验，避免为实验重新定义题目；按固定顺序保留每组首跑，不挑选更好看的重复结果。

本轮预定使用同一个已构建的评估二进制和 v1.5 全集，每组各三次：A 为正常机制；B 仅 attempt_limit=1；C 仅 semantic=false；D 仅 Builder 改为现有接入已使用的 deepseek-v4-flash-0731；E 仅 Screening 改为 qwen3.8-max-0902。每次与 A 对照，按 A→B→C→D→E 顺序执行并记录时间。模型实验只用进程环境覆盖，产品 `.env` 不改。若 A 仍需修程序，则以修复后程序重新建立 A，不混用不同二进制的结果。

## 1. 修复环消融

同一题目清单、目录快照、模型配置下，对照正常最多三次生成与最多一次生成。单次组遇到首轮失败就结束，预算、规则、SKU、已有件、锁定等交付检查全部保留；实验不会通过关闭校验使坏配置交付。

开关必须进入运行元数据，默认产品行为保持原三次上限。对同一用例逐题配对，分别记录正常组获胜、单次组获胜、双方通过和双方失败；统计成功交付、合理非交付、模型调用次数、token 使用（上游缺失明确标缺）及耗时。直接由程序证明非交付、无需模型的场景单独列出，不能拿来证明修复环有效。

每组至少三次独立重复，顺序交替或记录运行先后，避免时间差被误当功能效果。重复编号不是模型可复现随机种子。报告展示逐题证据及样本限制，不凭相差一道题就自动更换生产策略。

本轮装机题正常组 93/93、单次组 42/93，交付 69→18；单次组 token 少 19.07%、耗时少 46.22%。51 次失败均未进入预算区间（45 次偏低、6 次偏高），其中仅 6 次兼容报告 fail；因此主要证据是预算调整收益，不等同于性能/偏好质量改善。生产仍保留三次上限。失败说明写死“三次”的文案问题，以及另一个未闭合初筛 JSON 的处理问题，待固定二进制实验结束后修复，避免中途引入程序变量。

## 2. 语义检索消融

正常候选准备与仅核心候选准备配对。关闭语义扩充时不得调用 Embedding，也不能删除品牌/预算/兼容性/锁定约束。先确认软偏好题确实会触发语义路径，且有可独立检查的命中证据；仅硬校验通过率相同，不能据此判定软偏好同样满足。

指标除交付正确率外，补充与明确偏好对应的证据命中、候选变化、调用和耗时。若现有题目无法判断偏好质量，应明确为评估覆盖不足，再增加经审阅的新版本题目，不能事后改题制造胜负。

新评估产物的 `candidates` 保存本轮实际传入的候选、规格与 match_text 副本，提前非交付不沿用上一题证据。匹配文本存在只证明检索路径提供了内容，不自动证明安静、颜色或品质满足；诊断须列出实际选中 SKU 及文本原文，缺少可核验属性时保留未知。

## 3. 模型配对对照

固定完整程序机制，分别替换 Builder 或 Screening，一次只改变一个角色；每个角色保留当前模型作为基线。使用账号已有接入，实验不改变产品默认配置、不启用额度自动切换链。遇到模型不可用单列环境结果，不把静默换模型后的输出记到原模型名下。

报告优先回答哪些题出现了不同结果、调用/token/延迟差多少。没有已核验的计价信息就只报告用量，不编造费用；小样本不足以证明等效时不自动选型。

## 4. 解释质量评分

先定义少量能人工复核的分档例子，区分事实有依据、解释与需求相关、限制和下一步清楚。价格、参数、SKU 等可确定检查的事实继续由程序复验；Judge 仅补充解释质量，不能推翻硬校验。

优先重用已保存的 Builder 理由和程序非交付说明，不额外生成漂亮文案替代真实输出。Judge 使用与 Builder 不同模型家族，报告评分理由及证据引用，明确开发者校准样本的来源。评分未与人工参考对齐前只作诊断，不作发布门禁。
