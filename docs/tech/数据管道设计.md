# 数据管道设计

> 数据发布管道已具备采集运行、字段证据、隔离与不可变 release；本机定时任务已于 2026-09-21 移除。强制约束与来源决策记录见[数据规则](../data/数据获取与发布规则.md)，未完成工作见[路线图](../product/路线图.md)，实际运行命令见[运行手册](../ops/本地运行与部署.md)与[价格任务](../ops/价格任务.md)。

## 1. 设计结论

- **人工启动、文件留痕、条件发布、数据库投影**：采集由维护者在可见终端显式执行；低风险且证据完整的变化可以自动发布，高风险变化进入隔离区。任何失败保留上一份可用数据，不以空值、旧页面误解析或低质量来源覆盖正式数据。
- 本机定时任务已移除：Windows 计划任务、`pcdata scheduled-run` 与包装脚本已删除；价格与新 SKU 更新走 `cmd/importprices`、`collection-tools/` 和显式 `price publish`。以后确需周期采集，把同一 CLI 搬到持久 runner；GitHub Actions 无法直接更新本机 Docker 数据库，不能当调度器。
- **数据发布主链禁止调用大模型**。模型只允许在人工显式启动的离线候选辅助中使用，且输出强制进隔离区。
- 当前实现边界：管道只维护 AMD CPU 既有 SKU 的规格与证据，不发现新 SKU、不采集价格；NVIDIA 自动页面采集因条款限制排除。
- 已实现:`pcdata source/collect/normalize/review/publish/bootstrap/health` CLI,registry/run/evidence/review/release 五份 schema,ETag/robots/HTTP 安全门禁,运行幂等与互斥锁,不可变 release 与 last-known-good,parts/publication/evidence 的 Go 单事务导入。

## 2. 数据权威与布局

- Git 管理代码、schema、来源规则、seed 数据和人工 override(`scripts/data/` 下 sources.registry/lock、catalog/、schemas/、bootstrap JSONL)。
- `var/data/releases/<release_id>/`(gitignore)是本机发布的不可变事实，`current.json` last-known-good 指针只在 release 文件写完、全部门禁通过且数据库事务成功后原子切换；PostgreSQL 是当前 release 的运行时投影。
- 自动任务不执行 git add/commit/push。原始网页、API 响应和人工模型输出只保存在忽略目录，仓库和 release 只存 URL、哈希、最短证据摘要和适配器版本。

## 3. 来源与证据

- 来源必须先在 `sources.registry.json` 登记(id、kind、adapter、trust_tier、条款 URL、robots 策略、频率、failure_mode)并通过 `source check`;未登记、条款未检查或要求凭据未配置的来源不得执行网络采集。条款或 robots 变化自动禁用并隔离。
- 正式关键字段必须关联 evidence ID:SKU、field、value、source_url、captured_at、raw_sha256、method、excerpt。**主链只接受 `method=deterministic`**;`model_assisted` 候选只能进 quarantine,同次运行不能自动晋级。
- 运行 manifest 固定记录 run_id、来源与版本、HTTP 状态与哈希、候选/失败/隔离条数、发布决定和 `model_used`(主链必须 false);不记录 API Key、Cookie、Authorization、完整 prompt 或受限正文。
- 规格来源优先级：厂商官方型号页 > 许可明确的开放结构化库 > 锁定版本社区数据集 > 人工离线候选。价格只允许条款允许低频访问的公开零售/官方商城页面、结构化价格源和人工 CSV 兜底；官方 MSRP 可作参考观察，不冒充实时成交价。

## 4. 发布条件与隔离

自动发布(`--policy auto`)必须同时满足：来源全部启用且无登录/验证码/403/429/结构异常；SKU 精确身份匹配无歧义；所有变化有确定性 evidence;关键字段无来源冲突且 canonical/coverage/导入预检通过；无隐式删除或批量退休；价格变化在允许范围且变体一致；输入哈希与 review 一致；全程 `model_used=false`。

以下变化**必须隔离**，不覆盖上一正式值：

- 兼容关键字段(socket、内存代际、尺寸、TDP、供电、额定功率)改变；A 级来源冲突或同页双值。
- 价格相对上一快照变化超 25%,或同批多 SKU 异常同幅变化。
- 隐式删除、单批退休超 5%、大量字段突然为空、页面模板变化、模糊匹配、模型参与或人工临时 override。

隔离不阻塞其他来源和其他 SKU 的低风险批次；同一 SKU 保持 last-known-good 直到新的安全发布决定。新 SKU 只有 A 级来源、关键字段完整、身份精确且价格满足核心池新鲜度才自动进 `active_core`;否则最多 `catalog_only`。

## 5. 价格观察与安全选价

价格管道维护带日期的人民币参考价格，不提供实时价格、库存承诺、返佣链接或下单能力。

- `price_observations` 保存不可变原始观察：observation_id 由 SKU、来源、商品标识、价格、观察时间和原文哈希确定性派生；金额 `NUMERIC(10,2)` 十进制；数据库触发器拒绝 UPDATE/DELETE,重复 ID 仅在字段全同时幂等。`price_snapshots` 是发布批次，`prices` 是每 SKU 实际选中的报价。
- **CSV 契约**(固定表头):`sku,price_cny,currency,source_id,product_id,source_url,seller,price_type,stock_status,variant_match,observed_at,raw_sha256`。仅 `CNY`、正十进制两位小数、RFC 3339 带时区且不未来；`regular/sale` 可参与选择，`coupon/member/msrp` 只保留观察；只有 `in_stock + exact` 可参与选择。
- **确定性选价**(逐 SKU):过滤不合格观察 → ≥3 个不同合格来源取十进制中位数最近报价 → 1-2 个来源按登记优先级 → 并列按优先级/类型/时间/金额/ID 排序。新选价变化超 25% 隔离该 SKU 沿用旧值；批次异常数达 `max(3, 10%)` 隔离整批；无安全变化返回 no_change。
- price release v1 固定包含 observations/selection/review/manifest;Go 导入器重新校验哈希后在同一事务写入 run、observations、snapshot、prices,成功后原子切换 `var/data/current-price.json`。模型调用数固定为 0。
- **动态新鲜度**：不固化进 build,读取历史 build 时按快照与逐 SKU observed_at 动态计算——0-7 天 fresh、8-14 天 aging、>14 天 stale、缺价 unknown;过期价不把兼容性改 fail,但工作台、分享页和 Markdown 强提醒购买前核价。
- **自动价格来源保持禁用**:`serpapi_baidu` 已登记但 disabled,真实 canary 0/12 未达门槛(≥10 有购物结果、≥9 双商家精确匹配、零误匹配)；京东联盟已放弃，ZOL 为 permission_required 候选。任何后续结构化价格源必须先通过相同 canary 和双商家门禁；搜索摘要、模型回答不能升级为正式 observation。人工 CSV 是恢复通道。
