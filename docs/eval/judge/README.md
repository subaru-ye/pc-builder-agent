# 解释质量诊断

这里只评价已保存的选配理由、非交付说明，帮助发现“配置通过硬检查，但解释空白、不相关或误导”的问题。不是新的发布门禁，不代替真人评审。

当前规则和样例由 AI 编程助手编写，独立人工校准未完成。[评分规则](rubric-v1.md)给出三个维度和可供人工复核的锚点；[样本清单](selection-v1.json)固定八题、原运行第一次重复，覆盖普通交付、软偏好、已有件与非交付。这个小样本按诊断目的选择，不是随机抽样或总体质量估计。

```bash
go run ./cmd/evaljudge -source artifacts/eval/<原运行目录> -model deepseek-v4-flash-0731 -repeats 3
go run ./cmd/evaljudge -mode replay -dir artifacts/evaljudge/<诊断目录>
```

诊断复用现有 Screening 端点/key，但模型名仅在本进程内覆盖，产品配置不改。Judge 与来源 Builder 必须为不同的已识别模型家族，两者不能使用切换链。来源先经过同一套冻结题目、判卷与多轮证据验证，再提取原文；不另写漂亮解释去替代真实结果。空解释由程序单列，计 0 档且零调用，不表述为模型发现了虚假事实。

每个样本重复评分三次，保留逐次原文、分档理由、可定位引用、逻辑调用与已知 token。引用必须同时指向被评解释和提供的事实片段；引用存在只证明可定位，不证明语义判断正确。没有硬件噪声实测、颜色或性能证据时不能用模型记忆补真值，评分也不能推翻原预算、兼容和溯源校验。

评分请求声明 JSON 输出类型与评分结构 schema，并按稳定的 key 顺序展开原始事实字符串，避免将事实 JSON 双重编码。要求截取连续短引用，不重组字段或补括号；输出围栏、假引用仍记无效，不作宽松补救。请求声明不代表上游一定遵守；实测仍存在无效输出和语义误判，不能称为已可靠自动判卷。首次真实诊断的协议失败及修复重跑分别保存，详情见[运行记录](../运行记录.md)。

原评估程序继续复验结构化报价、SKU、规格和非交付证据；这不代表任意自由文本中的所有硬件主张都已得到程序证明。解释中的不实推断仍是此诊断与后续人工复核的对象，不能把 Judge 的“依据表达”分数当成事实认证。

产物位于 `artifacts/evaljudge/`：inputs.json、selection.json、rubric.md、meta.json、results.jsonl、report.md。写入来源、规则、清单和程序哈希，首个模型调用之前先冻结输入，每次评分完成即追加记录。评分调用失败或输出无效记错误，不删记录、不纳入均值；完整重放仍须确认这些错误被原样保留。

重放需要原 eval 目录仍可访问：核对原结果哈希并重提取原文，拒绝事后润色或只改分数；来源记录里的需求还须与冻结题目一致，避免判卷和 Judge 各用一份需求。重新校验所有引用、评分和重复数量，写 replay.md，不调用模型。下一步人工校准应由实际人工填写参考评分，记录分歧并在新规则版本修订；AI 锚点或单元测试不能填充人工一致率。
