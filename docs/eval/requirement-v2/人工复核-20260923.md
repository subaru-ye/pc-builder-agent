## 更正 1:rdy-budget-conflict-blocks(development)

- 修正:`expected.missing_fields ["use_case.type"] → ["use_case.type", "existing_parts"]`。
- 理由:该 case 状态中 `existing_parts` 为 unknown,v2 最低确认矩阵将已有配件表态列为必填(unknown 不能默认为空)。同形状状态(budget conflict + 其余 unknown)在 2026-09-22 人工复核通过的 extraction 金标 `ex-budget-conflict-family` 中期望缺失即为 `['use_case.type', 'existing_parts']`;`rdy-existing-unknown-blocks` 与 `rdy-fresh` 也与该规则一致。原金标是建基时按 v1 行为(必填不含 existing_parts)误标,与其余冻结金标内部矛盾。

## 更正 2:rdy-holdout-owned-basis(holdout)

- 修正:`expected.missing_fields ["budget_basis"] → ["use_case.titles", "budget_basis"]`。
- 理由:该 case 状态 `use_case.type=productivity` 且 `use_case.titles=unknown`,v2 条件必填要求生产力用途至少一个软件或任务(与 `rdy-productivity-no-titles` 一致);`budget_basis` 缺失维持不变。原金标同样按 v1 行为误标(titles 非条件必填)。该 case 属 holdout,本次只做静态修正,不参与 dev/cal 运行。
