# Crawl4AI 商品查询实测（2026-09-13）

## 范围与方法

使用当前产品 `planning.NewWeb(Store)` 的真实 Search / Read 方法，连接正在运行的 Crawl4AI 0.9.3 Docker 服务。Search 经过现有 SerpAPI 账户检查及 PostgreSQL 共享配额预留。Codex 根据返回链接选择页面，不调用 Screening / Builder 模型；本次是工具链测试，不能算自主规划或配置交付端到端验收。

预设并遵守上限：2 次 SerpAPI 搜索请求、6 次 read_page；无自动重试。另有 Search 方法内部的 2 次 SerpAPI 账户查询，不计作搜索请求。模型、Embedding、买手接口调用均为 0。未写入商品、价格、方案或正式版本，仅共享搜索额度记录正常增加。

搜索词：

1. `AMD 5900X 京东 价格 参数`，约 6.3 秒。
2. `蓝宝石 RX 9060 XT 16GB 淘宝 价格`，约 3.9 秒。

两次各返回 8 个结果，当前 Search 输出的 title/text 全为空，实际模型只能看到链接。结果主要是资讯、聚合站、论坛和百度购物入口，没有直接京东/淘宝详情页。尚未保留本轮 SerpAPI 原始响应，因此不能判定空字段来自上游返回还是项目字段解析；需要单独修查。

## 判断

1. Crawl4AI 能实际执行浏览器抓取，并非只能读取静态 HTML；厂商规格及部分商品卡片可读。
2. 当前链路尚不能作为可靠的自动电商报价采集方式。6/6 HTTP 工具成功不能算 6/6 有效资料；登录页、空壳页、旧优惠、变体不明都需要分别处理。
3. ZOL 样本证明抓取能力与向模型交付有效正文是两回事。只加浏览器不解决当前正文截断和导航噪声。
4. 网页路线适合补公开规格、支持表、资料线索；买手价格路线继续独立使用。网页里出现的价格也须按来源性质、日期、型号和购买条件复核，不自动升格为平台实价。

## 后续需要修复（本轮仅测试，未修改运行逻辑）

- 核对搜索原始响应与标题/摘要解析，改进商品及厂商资料的结果选择；不能把搜索聚合入口当目标商品页。
- 返回最终落地 URL 及页面状态，明确识别登录、验证码、跳转入口、无商品内容等情况，避免 HTTP 200 被误解为取证成功。
- 保存完整正文作为证据底稿，按正文结构提取相关段落/表格，支持按需继续读取；不要简单扩大每轮模型上下文或只截取网页开头。
- 价格与规格分别提取，保留发布日期、观察日期、商家、准确变体和未知项；旧优惠和未选变体不能生成已核验报价。
- 使用这些真实响应离线回放，再用少量明确网址验证修复；后续模型自主搜索、提取、修正和正式交付仍需单独验收。
