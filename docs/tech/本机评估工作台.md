# 本机评估工作台

工作台入口 `/eval`，沿用现有 Next.js、React Query、中文设计 token 和 Playwright。独立 Go 程序 `cmd/evaldesk` 读取已有评估产物，比较和复核留在 Go；Next.js 只代理、展示，不定义另一套判卷规则。

## 启动

两个 Git Bash 终端，从仓库根目录启动。无需 PostgreSQL、Redis、生产 API 或模型凭据；不执行真实评估。

```bash
# 终端 1：默认只监听 127.0.0.1:8086
cd /c/code/pc-builder-agent
go run ./cmd/evaldesk -root .

# 终端 2：显式开启本机评估代理，Web 同样绑定本机地址
cd /c/code/pc-builder-agent/web
EVALDESK_API_BASE_URL=http://127.0.0.1:8086 pnpm dev --hostname 127.0.0.1
```

打开 [本机评估工作台](http://127.0.0.1:3000/eval)。以此方式启动时，产品首页顶栏也显示「本机评估」。生产启动不设置 `EVALDESK_API_BASE_URL`；本机查看服务和前端均须绑定 loopback，Host 校验不能代替本机监听。

Go 的 `-root` 为包含 `artifacts/` 的项目根目录，`-addr` 只接受 loopback 地址。改变端口时同步前端环境变量。前端代理配置变化需要重启 Next.js。停止时在对应终端按 Ctrl+C，不涉及历史文件或基线操作。

## 查看流程

左侧导航切换独立工作页面；顶部的基线/候选运行选择器仅在「评估运行」「运行对比」显示。题库、提交记录和时间线可以直接浏览，无需先选对照组。

1. **评估运行**：按产物时间查看历史成绩与调用量。运行以北京时间、题库版本和通过情况辨认，缺失时间不从目录猜测。展开「版本证据与完整性」查看原始标识及缺项；点击运行时间可自比查看本次运行题目，点击「查看题库」进入它保存的完整题库。
2. **运行对比**：显式选择基线（作为参照的历史评估）和候选（要与它比较的另一轮），点击「对比运行」。先看「改了什么」，再看共同题的指标增减，通过「退步」「调用变化」定位问题。增减均表示候选相对基线的变化，基线不代表官方标准或最佳成绩。点击「基线题库」「候选题库」可分别核对两侧冻结题目。
3. **代码提交记录**：只列出评估产物关联的提交，不是整个 Git 仓库的提交历史。相同完整提交标识合并为一条，显示本机 Git 中的标题、提交时间及关联评估；缺有效提交标识的运行单列。选择关联运行后，点击「查看提交文件」进入独立提交详情，查看文件变化与当时的工作区状态，也可点击「查看该运行题库」。完整提交标识保留在折叠证据中。
4. **题库与评估集**：从版本目录或左侧版本子菜单进入指定版本。相同版本名下按完整有效内容指纹分组；不同指纹分别展示，缺失或无法识别指纹的运行独立保留，不因版本名称相同就断言题目相同。每份内容记录显示已知冻结题数和关联运行，可选保存该题库的运行，再点击「查看完整题目」。独立题库详情支持按题号、标题、输入内容搜索及题目类型筛选，展开逐轮冻结输入、中文期望摘要和完整期望记录；未执行题也可查看。
5. **溯源时间线**：按产物中的评估时间串起运行、题库题数、模型配置和当时的仓库提交，提交时间单独标注。缺运行时间的记录归入「时间未记录」。可搜索时间、题库、模型或提交说明，并分别进入「查看题库」「查看提交」。

题库详情、提交详情与「运行版本档案」分开显示，通过「对应代码提交」「查看关联题库」「运行版本档案」等入口互相跳转。版本档案集中展示模型、商品快照、原判卷及折叠的完整版本证据。查看资料使用独立 `run` 参数，不改变现有基线/候选选择；当前页面、题库版本和展开题目保存在 URL 中，支持刷新及浏览器前进/后退。旧链接 `view=provenance&run=…` 继续兼容为该运行的题库详情。

点击「查看本题运行结果」进入该次运行的单题证据；对比页点击题目进入双栏详情，默认选中候选中失败的一次重复。可切换重复、跳到失败轮次，查看冻结输入与期望、最终可见回复、模型原回复/格式重试、选件和失败证据。原判卷与统一复核分别显示。只有显式选为基线/候选，或进入某次运行的单题结果时，才更新对应选择；选择仅保存在本页 URL，不写入基线配置。

时间线顺序不代表代码继承关系。提交文件列表来自该提交相对第一父提交的变化（首次提交视为新增），不包括运行时未提交改动，也不是两次实际程序之间的完整源码差异。缺少本机 Git 或历史提交时仍可查看冻结题库；缺冻结题库时不从当前 `docs/eval` 补造。「重新读取」仅重新扫描已有产物；格式旧、记录中断或无法完整复核时显示状态和原因，不调用模型补齐。

「改了什么」按模型配置、实际程序、题库与商品数据等类别呈现可读说明。模型配置按选配/初筛/检索角色逐项比较安全参数；完整哈希留在「版本证据与比较口径」。代码区可直接查看本机 Git 中已记录提交的标题与时间，同时注明运行时的未提交修改。提交说明描述的是当时仓库记录；只有两侧都保存并通过校验的源码清单才能列出实际构建输入的文件变化，缺失时明确指出缺哪一侧，不把文档提交或哈希差异写成实际程序的完整修改说明。

## 指标和比较口径

- **执行通过**按一次题目重复计数。已知计划次数时分母为冻结题数 × 请求重复数；缺失、执行错误和数据不足不算通过。旧产物计划次数缺失时只展示已有记录情况，不能视作完整运行。
- **全部重复通过**要求一题每次计划重复均通过且无 veto/data-error，显示通过题数/冻结题数。重复数未记录或身份异常时比例未知，不从看起来恰好有三次的历史记录推测 Pass³。
- **严格代码回归**直接调用 `evalsuite.CompareChangeDirs`，复用 `AuditRun`、原判卷重放、当前判卷复核及同题/同模型/同完整数据/同机制/至少三次重复检查。版本标识和原成绩不同不代表必然因果。
- **跨题库**比较冻结 `Case` 的内容与期望，仅完全相同的共同题进入结果与用量差异。新增、删除、修改题单列；缺冻结题目的运行无法判断共同题。不把两套不同题数的总量直接当收益。
- **多因素或证据不足**降为观察比较；条件及拒绝严格比较的原因同时列出。不完整或未通过原始证据复验的记录不产生可信的统一复核胜负。判卷版本缺失显示「未记录」，旧分支重放是工具规则，不是补造历史版本号。
- **原成绩/统一复核**首跑记录保持原样；统一复核使用当前 `independent-v2` 在内存计算。运行列表显示原成绩，比较主表显示共同题复核成绩；总览及单题均能展开查看原成绩。以后判卷演进应沿用项目独立版本约定。
- **用量**分模型和 Embedding 逻辑调用，显示记录覆盖及返回 usage 的模型响应数；token 是已返回的已知部分，不包括 Embedding token、未返回的用量或适配器内部 HTTP 重试。缺数据不记作零、不估算费用；不可比用量的差值显示未知。耗时仅为记录累计值。

## 版本证据

旧运行只展示已记录的元数据。历史目录中若保留完整商品规格和价格，可用于现场严格核对，但 `meta.json` 的原始数据指纹仍显示「未记录」，不把现场计算当历史记录。

今后的 `cmd/eval` 新运行增加以下最小证据，`cmd/evalchange` 沿用该 runner：

| 产物 | 内容 |
|---|---|
| `meta.json` 的 `prompts` | 独立提示词 SHA256、组件指纹、原文文件名和格式版本 |
| `prompts.json` | 按角色冻结实际编译的静态提示词及 Builder 输出契约；只创建新文件，拒绝覆盖 |
| `meta.json` 的 `data` | 实际加载的完整 `SnapshotView` 指纹，涵盖商品目录规格和价格 |
| `started_at` / `finished_at` / `status` | 运行生命周期；完成不等于全部通过；调用上限造成未执行时保留未完成状态 |

已声明的提示词和数据证据由 `VerifyRunEvidence` 校验，防止原文与标识不一致。旧运行缺字段保持兼容。提示词指纹不覆盖每次动态请求；动态输入、候选和回复仍从 cases/results 查证，组装逻辑由实际程序版本区分。数据指纹不涵盖向量索引，历史二进制也不能仅凭 checkout commit 恢复精确源码。

## 只读接口与边界

`internal/evaldesk` 只扫描 `artifacts/eval` 和 `artifacts/evalchange`，包含后者嵌套 `runs/`。识别 meta/cases/results，不把日志目录当公开文件服务。运行 ID 是由相对路径生成的不透明标识；请求不能指定任意文件路径，符号链接产物不读取。

| GET 接口 | 响应 |
|---|---|
| `/api/evaldesk/runs` | 运行摘要、完整性说明、当前复核版本 |
| `/api/evaldesk/compare?baseline=…&candidate=…` | 变化条件、共同题指标、逐题分类 |
| `/api/evaldesk/cases?baseline=…&candidate=…&case=…` | 单题冻结输入和允许展示的证据；基线可省略 |
| `/api/evaldesk/timeline` | 按真实运行时间排列的题库、模型与本机提交摘要 |
| `/api/evaldesk/provenance?run=…` | 该运行的完整冻结题库、逐轮输入期望、提交说明及允许展示的文件清单 |

展示契约为 `web/src/lib/evaldesk/types.ts`。DTO 采用字段白名单和文本凭据脱敏，不发送完整模型配置、候选目录、原始日志、上下文/思考轨迹或本机绝对路径。提交读取只接受产物中的完整提交标识，不接收请求提供的 Git ref/路径，不自动 fetch、不返回源码补丁；文件列表有类型和数量限制。题库接口只返回冻结输入与期望，模型回复仍由单题证据接口读取。API 无写路由、无 CORS 授权、无静态产物下载，响应 `no-store`；仅接受本机 Host/Origin。Web 使用已有 React 文本渲染，不执行产物中的 HTML。

第一版支持本机浏览和复核。暂不提供自动运行、基线升级、定时评估、线上监控、账单估算、判卷选择器或完整源码 diff；旧记录缺失证据无法恢复。内存缓存依文件大小和修改时间失效，不承担对抗同时恶意改写本机文件的取证保证。
