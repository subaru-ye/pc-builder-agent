## 1. 阶段目标

阶段 2 不追求实时比价，也不建设全站爬虫。目标是把当前一次性的离线数据制作方式，升级为可在本机按期无人值守运行、变化可解释、异常可隔离、失败不污染正式数据的数据发布系统。

阶段结束时应具备：

1. 每个正式零件关键字段都能追溯到锁定数据集、官方页面、说明书或经过批准的人工例外。
2. Windows 任务计划程序能在电脑开机时定时执行；错过任务后于下次开机补跑。
3. 原始采集、候选、隔离项、发布决定和正式 release 彼此分离。
4. 低风险且证据完整的变化可以条件式自动发布；关键字段变化、冲突、异常删除和异常价格保持上一正式值并隔离。
5. 价格仍是日期化参考快照；核心推荐池平均年龄不超过 7 天，单件最大年龄不超过 14 天。
6. 八个品类的目录数量各不少于 50，只有满足规格、价格和证据门槛的 `active_core` 零件可以被 Agent 推荐。
7. 常规定时任务不调用大模型；模型只作为人工显式启动的离线候选辅助，不直接写正式数据。
8. 正常周无需逐条审核；人工时间主要用于隔离项、来源规则变化和新增适配器，稳态目标不超过 30 分钟/周。

本阶段不要求公网部署。当前自动化运行在开发电脑上：电脑关机期间不会采集，开机后补跑。只有未来要求 24 小时持续更新时，才需要 NAS、服务器或受控 CI runner。

## 2. 当前基线与缺口

截至 2026-08-24，P11 完成后的仓库基线为：

- 160 个零件，八类各 20 个；160 个零件均有 `2026-07-28` 价格。
- `pc-part-dataset` 锁定在 commit `c52a04ca9465c83997ed335f7767b09a2005dd26`，提供产品级候选规格，美元价格被明确丢弃。
- `dbgpu==2025.12` 作为 GPU 芯片级 TDP、板长和供电接口兜底。
- `scripts/data/catalog/*.json` 是人工选品与 override 输入，`scripts/data/parts/*.jsonl` 是确定性 bootstrap 产物。
- `cmd/importparts` 全量 upsert 零件，`cmd/importprices` 兼容历史四列快照，P12A 使用 `pcdata price` 与 `cmd/importpriceobservations` 发布可审计快照，`cmd/embedparts` 当前全量重算 embedding。
- P11 已增加字段 evidence、条件 GET、run/checkpoint、quarantine、release v2、last-known-good、`catalog_state` 和 Windows 本机调度。
- AMD 官方适配器固定覆盖当前 13 个 AMD CPU；数据库当前 release 有 65 条已验证字段 evidence。
- P12A 已具备价格 observation、确定性选价、逐 SKU last-known-good 和产品过期提示；历史 160 条价格仍是 bootstrap。

阶段 2 剩余缺口为：

- 首个许可明确的自动价格来源，以及连续两个真实 weekly 周期。
- 八类目录扩容、新 SKU 候选生命周期和更多厂商品类证据覆盖。
- 性能分许可、版本化刷新和变化项增量 embedding。

因此阶段 2 第一项工作是可信发布与恢复协议，而不是直接增加大量网页采集器。

## 3. 范围边界

### 3.1 范围内

- 来源登记、版本锁定、许可与自动访问状态记录。
- 低频、合规、确定性的官方来源和许可开放数据适配器。
- 原始哈希、字段证据、候选标准化、机器 Diff、风险分类和不可变批次发布。
- Windows 任务计划程序、开机补跑、运行幂等、互斥和健康检查。
- 低风险条件自动发布、高风险隔离、last-known-good 和数据库原子投影。
- 条款允许的公开零售/品牌商城价格观察，以及规范人工 CSV 兜底。
- 价格过期提示、核心推荐池自动退出和恢复。
- 八类零件目录扩容、别名和精确变体匹配。
- CPU/GPU 性能分的许可核验、版本化导入和覆盖率报告。
- 变化零件的增量 embedding。

### 3.2 范围外

- 实时价格、库存或成交价承诺。
- 京东联盟 API、返佣、推广链接和订单能力。
- 绕过登录、验证码、访问控制、robots 或平台限流。
- 未经许可复制或再分发第三方数据库。
- 让大模型凭常识补齐事实，或在定时任务中调用模型。
- 无条件把候选、模糊匹配或异常数据发布到正式数据库。
- 24 小时在线调度、正式云部署和生产 SLA。
- Intel/LGA1851 平台和新品类；它们仍属于阶段 3。
- 数据管理 Web 后台；首版使用 CLI、JSON/Markdown 报告和本机文件处理隔离项。

## 4. 数据分层

| 状态 | 含义 | 可被 Agent 推荐 | 价格要求 | 自动晋级上限 |
|---|---|---:|---|---|
| `candidate` | 新发现、身份或证据尚未完成 | 否 | 无 | 不能自动越过证据门禁 |
| `catalog_only` | 规格基本可用，但证据或价格未达到核心池门槛 | 否 | 可缺失或过期 | B/C/D 来源通常最多到此 |
| `active_core` | 关键规格完整、证据通过、价格新鲜 | 是 | 平均 ≤7 天，单件 ≤14 天 | 仅 A 级具体型号来源且全部门禁通过 |
| `retired` | 停产、长期无货、重复或明确不再维护 | 否 | 只保留历史 | 批量退休不得自动执行 |

`parts.active` 在兼容期继续作为运行时过滤字段；发布器必须保证只有 `active_core` 对应 `active=true`。不能依靠手工 SQL 修改二者。

## 5. P11–P14 顺序

### P11：来源证据、本机调度与安全发布基座

实施进度：已完成。13 个固定映射的 AMD CPU 官方页可低频条件采集，65 条字段 evidence 已进入 release v2 和 PostgreSQL；正式五项 Windows 任务已安装，两次一次性 Task Scheduler 验收均命中 13 个 304、保持 publication/evidence 幂等且模型调用为 0。验收细节见[P11 验收记录](../acceptance/P11-验收记录.md)。

目标：建立 `schedule → source check → discover/collect → normalize → validate → risk classify → publish/quarantine` 主链。

主要交付：

- 来源登记、证据 schema、run/checkpoint、review 和 release manifest。
- 不可变 release、last-known-good、quarantine 和失败恢复。
- `pcdata source/collect/normalize/review/publish/health/scheduled-run` CLI。
- 低风险自动发布规则和高风险隔离规则。
- 兼容现有 catalog、parts JSONL 和 Go 导入命令的发布器。
- Windows 任务计划模板、错过任务补跑和 Compose service 健康检查。
- 定时任务零模型调用门禁。

DoD：当前 160 个零件完成零语义变化回灌；至少一个官方来源能增量采集；低风险批次自动发布、高风险批次隔离；连续两个计划周期没有发布事故。

### P12：价格观察、新鲜度与安全选价

实施进度：P12A 已实现。P12B 已实现 SerpApi Free/Baidu Shopping 适配、240 次月度硬门禁、12 SKU canary、双商家选价、96 SKU 待激活核心池和每日 7 SKU 调度；由于本机尚未配置 Key，真实 canary、96/64 状态切换、每日任务安装及两个 14 天轮转周期仍未完成。ZOL 保持 disabled candidate。实现细节见[P12 价格观察设计](../tech/P12-价格观察与安全选价设计.md)。

目标：维护核心推荐池的参考价格，不做全目录实时比价。

主要交付：

- 标准 `price_observations`、公开零售/品牌商城适配器和人工 CSV 导入器。
- 每个自动来源的条款、robots、访问频率和页面结构检查。
- 精确 SKU/容量/颜色/版本匹配、库存与价格类型过滤。
- 同一 SKU 多个合格报价的确定性选择规则。
- 超过 25% 的波动、商品失效、页面结构变化和单一来源异常进入 quarantine。
- 低风险价格批次自动形成不可变快照；失败时保留上一快照并增加 stale 年龄。
- Web/API 继续明确“参考价、非实时价”和快照日期。

DoD：连续两周自动产生核心池价格观察与发布决定；安全批次可自动发布，异常批次不替换上一有效快照，Web 正确显示过期状态。

### P13：SKU 扩容与规格维护

目标：每类目录达到至少 50 个，推荐池仍保持克制。

主要交付：

- 接入许可明确的开放目录候选源；优先评估 BuildCores OpenDB，并履行 ODC-By 署名要求。
- 厂商官网/说明书确定性适配器和品类字段清单。
- 品牌、型号、容量、颜色、修订版的别名与冲突检测。
- 按品类小批量扩容，每批 10–20 个 SKU，可独立隔离和回滚。
- A 级具体型号证据、精确身份、关键字段和新鲜价格全部满足时才可自动进入 `active_core`。
- 其他安全候选最多自动进入 `catalog_only`，不为数量指标降低门槛。

DoD：八类目录各 ≥50；错误级规则所需字段在 `active_core` 中 100% 完整；扩容后的规则 golden、产品 E2E 和旧 build 回放全部通过。

### P14：性能分、增量向量与运维封板

目标：补齐性能数据和低成本日常运行。

主要交付：

- 先完成性能数据的许可与再分发评估，再实现版本化适配器。
- CPU/GPU 性能分覆盖率 ≥80%；缺失继续显示 unknown，不由模型估分。
- 按 `embedding_text + provider + model + dimensions` 指纹增量生成向量。
- 完整调度告警、运行统计、release 回滚和恢复演练。
- 来源失败率、价格年龄、证据覆盖率、自动发布率和隔离项处理时间报告。
- 将本机任务迁移到在线 runner 所需的前置清单，但不要求实际部署。

DoD：连续四周按计划运行，正常批次无需人工批准；无自动发布事故；稳态人工维护平均不超过 30 分钟/周，阶段 2 验收可复现。

## 6. 条件发布政策

### 6.1 可以自动发布

- 已登记且条款状态有效的来源。
- 精确 SKU 身份和确定性适配器输出。
- 完整 evidence、无来源冲突、无关键字段异常变化。
- canonical、coverage、规则 golden、导入预检全部通过。
- 无隐式删除、异常空值、批量退休或模型参与。
- 价格变化不超过 25%，且商品变体、库存和价格类型符合规则。

### 6.2 必须隔离

- 已有 SKU 的兼容关键字段变化。
- 来源冲突、模糊匹配、页面结构变化或证据缺口。
- 价格跳变、异常批量变更、隐式删除或批量退休。
- 登录、验证码、403、429、robots/条款变化。
- 任何模型辅助产物或临时人工 override。

隔离项不会自动覆盖 last-known-good，也不要求立即处理。它们可以等待人工核验、适配器修复或新证据；其他独立 SKU 仍可继续发布。

## 7. 推荐提交粒度

1. `docs: 规划阶段2数据自动化`
2. `feat(data): 增加来源登记与证据 schema`
3. `feat(data): 增加运行检查点与本机调度骨架`
4. `feat(data): 增加风险分类和安全发布器`
5. `feat(db): 增加目录状态与发布批次`
6. `ops(data): 增加 Windows 定时任务与补跑`
7. `feat(data): 增加价格观察与选择规则`
8. `feat(web): 展示价格新鲜度与过期状态`
9. 按来源、品类分别提交适配器和 SKU 扩容。
10. `feat(data): 增加性能分与增量 embedding`
11. `ci: 增加阶段2数据健康门禁`
12. `docs: 记录阶段2验收`

单个提交不得同时混入来源升级、canonical schema 变化和大批 SKU 内容修改，否则无法判断数据变化来自哪里。

## 8. 阶段退出标准

- 八类目录各 ≥50，`active_core` 中错误级规则字段证据覆盖率 100%。
- 核心推荐池价格覆盖率 100%，平均年龄 ≤7 天，单件最大年龄 ≤14 天。
- CPU/GPU 性能分覆盖率 ≥80%，无来源的值保持 unknown。
- 每次发布均有来源锁、run manifest、证据覆盖、机器 Diff、风险分类和发布决定。
- 低风险批次可自动发布；高风险批次保持 last-known-good 并进入 quarantine。
- 常规定时任务模型调用次数为 0。
- 采集、解析、导入或 embedding 失败不能产生部分正式更新。
- 连续四周按计划运行，稳态人工维护平均 ≤30 分钟/周。
- Go、Python、Web、OpenAPI、Live 主路径和历史 build 回放通过。
- 阶段 1 最终 Live/真人盲评若在数据变化之后执行，必须使用最新正式 release。

## 9. 开工裁定

P11 开工时固定以下决定：

- 当前主调度器为 Windows 任务计划程序，不要求线上部署；错过任务在开机后补跑。
- Git 管理代码、schema、来源规则和 seed；自动 release 使用本机不可变文件和数据库发布记录，不后台提交 Git。
- PostgreSQL 是当前 release 的运行时投影，发布使用事务和 advisory lock。
- 京东联盟 API 路线已放弃；P12 只接条款允许的公开页面、明确授权的结构化来源和人工 CSV。
- 常规定时任务不调用大模型；人工模型辅助结果只能进入 quarantine。
- 公开数据集只做候选和非关键字段来源，关键兼容字段优先使用具体型号厂商证据。
- 新 SKU 只有 A 级具体型号证据和全部核心门槛满足时，才可自动进入 `active_core`。
- 不把网页可访问等同于允许自动采集；registry 必须记录许可、服务条款、robots 和频率限制。
