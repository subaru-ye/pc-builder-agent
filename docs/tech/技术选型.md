# 装机配置单 Agent — 技术选型(ADR)

> 2026-07-26 · 技术栈决策记录,语言/框架/模型供应商以本文为准
> 冲突声明:本文**取代**[设计方案](../装机Agent设计方案.md) §三中「Google ADK(Python)」与「LiteLLM 挂任意模型」的措辞;架构、A2A schema、规则表、表结构仍以设计方案为准。

## ADR-001 后端语言与 Agent 框架:Go + ADK-Go

- **状态**:已定(2026-07-26)
- **候选**:Go + ADK-Go / Python + ADK / TypeScript + Pi([earendil-works/pi](https://github.com/earendil-works/pi))
- **决策**:Go + [google.golang.org/adk](https://github.com/google/adk-go)(ADK-Go,已发 2.0,含 workflow/loop 编排原语与内置 dev UI launcher)
- **理由**:后端语言意向是 Go;ADK-Go 让 Go 意向、主流框架 ADK 经验、A2A 学习目标、免费调试 UI 四者兼得。Pi 出局:TypeScript 绑定与 Go 冲突,且其设计立场是刻意不做多 Agent 编排与 A2A;Python 出局:与语言意向不合(它是 ADK 旗舰版本,文档最全,作为查资料的对照版本继续存在)。
- **代价与对策**:社区教程/示例多为 Python 版 → 遇问题对照 Python 文档翻译成 Go API,优先看 pkg.go.dev 与 adk-go 仓库示例;LiteLLM 是 Python 独有 → 见 ADR-004。

## ADR-002 A2A:官方 a2a-go SDK

- **决策**:单跳拆分(mvp.md P5)使用 [a2aproject/a2a-go](https://github.com/a2aproject)。
- 消息 schema 的 Go struct 定义于 `internal/schemas`,与设计方案 §四对齐;字段变更回写设计方案,不在代码里静默漂移。

## ADR-003 数据层:PostgreSQL 16 + pgvector、Redis 7(沿用,不重开选型)

- 记忆基座(PG/pgvector/Redis)是学习目标本身,语言切换不影响。
- 访问层:pgx + pgvector-go + go-redis。不引入重 ORM;如需类型安全查询生成可后补 sqlc,P1 时现场定。

## ADR-004 模型供应商:阿里百炼(Qwen 一站式)

- **决策**:chat 与 embedding 都走百炼 **OpenAI 兼容端点**,一个 key 搞定。
- 分档策略:初筛 Agent 用低价档 qwen,生成 Agent 用旗舰档 qwen;embedding 用百炼 text-embedding 系(全库 20–30 SKU × 8 类,用量极小)。
- **具体型号与单价实现当日查百炼文档,不在任何文档写死**(型号迭代快,与"不写死 API 签名"同一纪律)。
- 备选:硅基流动(同为 OpenAI 兼容,想横向对比 DeepSeek/GLM 时切换,迁移成本≈0)。

## ADR-005 数据管道:Python 3.12 + uv

- **决策**:数据导入/embedding 生成/性能分脚本用 Python,与 Go 服务端并存,边界 = `scripts/` 目录。
- **理由**:dbgpu 是 pip 包、passmark-scraper 是现成 Python 脚本;一次性/低频运行的工具,用 Go 重写纯属浪费。

## ADR-006 客户端:MVP 零自研;阶段 1 用 Next.js + React

- **MVP**:ADK-Go 内置 launcher 的 Web UI(嵌入 host 二进制)+ CLI 脚本,零自研前端。
- **阶段 1**(2026-07-26 已定):Next.js + React。理由:生态最大、chat 流式交互组件成熟;SSR 直接解决公开链接分享页的 OG 预览与首屏渲染(PRD FR-603);与设计方案 §七原候选一致。
- **边界纪律**:Next.js 只承担前端渲染与分享页,业务 API 全部在 Go 服务端;不用 Next 的 API routes 写业务逻辑,避免出现双后端。
- UI 组件库与状态管理方案到阶段 1 启动时再定,不提前锁。
