## 变更

- L3-102 的期望增加 `clarify_fields: ["budget_cny"]`：必须追问预算。
- L3-103 的期望增加 `clarify_fields: ["resolution"]`：必须追问分辨率。
- 其余 28 条题目不变。新清单为 [v1.1.json](../../../internal/evalsuite/testdata/suites/v1.1.json)，冻结时间见 `created_at`。原 v1 清单保留，但不能用修改后的当前题库冒充 v1；恢复旧题目需使用历史副本或对应 Git 版本。

S1 拦截空回复、JSON 和代码块；S3 检查实际问到了哪些缺失信息。比如“请问预算多少？”可通过预算题，“好的，我来推荐”或只问分辨率不能通过。匹配采用中文短句内主题词与询问/请求词规则，不调用额外模型；它仍可能误判特殊表达，争议时应复核保存的原文。

## 留存与重放

新运行的 `results.jsonl` 保存 `screening.text`（最终可见回复，不含思考内容）。`meta.json` 标记 `record_schema_version=1`；replay 从保存的 `cases.json` 取期望，从回复原文重新提取需求单并判 S1/S2/S3。

- 实际空回复会失败；新格式记录丢失回复会报错。
- 旧记录缺少原文时标为“部分重放”，保留旧分数，不宣称已重新判过。
- 对可重判记录比较完整断言、veto 和归因，失败原因变化也会被发现。
- 执行错误仍是执行错误，不把残留文本当成功回复。replay 退出 0 表示可重判记录一致，不代表所有用例通过；退出 1 表示判分变化，退出 2 表示产物/配置错误。

## 使用

从仓库根目录执行：

```bash
# 离线检查当前 30 题与清单，不连接数据库或模型
go run ./cmd/eval -mode check -suite internal/evalsuite/testdata/suites/v1.1.json

# 固定模型下建立真实基线：读取数据库、调用模型
go run ./cmd/eval -mode run -suite internal/evalsuite/testdata/suites/v1.1.json -snapshot-date 2026-07-28 -seeds 3

# 对本次生成的目录重放，不调用模型
go run ./cmd/eval -mode replay -dir artifacts/eval/<运行目录>
```

真实运行前确认快照存在、builder 为 `qwen3.8-max-0902`、screening 为 `deepseek-v4-flash-0731`、切换链为空，并显式设置 `BUILDER_REASONING_EFFORT=none`；未设置时该非默认模型会回退到 low，真实工具调用检查会被接口拒绝。示例快照日期沿用已有基线，并非最新商品数据。旧 v1 的 90% 不能作为新模型或 v1.1 的成绩。

后续冻结新版本的通用操作见 [v1 版本登记](v1.md)，实现边界见 [评估设施](../../tech/评估设施.md)。
