# 偏好记忆评估（场景草案，金标未冻结）

> 2026-09-27，分支 `codex/memory-foundation`。对应设计:[偏好记忆设计草案](../../tech/偏好记忆设计草案.md)。
> 状态:**仅场景草案**。当前产品链路仅支持用户显式保存稳定偏好、按显式选择的 subject 手动召回、逐项确认；
> 尚无自动提取、初筛或 Builder 模型注入。本目录尚无数据集、manifest、gates 或 runner 入口；
> JEV 接入不是本阶段评估的前置条件。后续若冻结金标，应按实际产品合同建设，不把本草案当作已通过的评估。

## 通用判定原则（对所有场景生效，非金标）

1. 用户确认的当前需求永远高于历史记忆;两者冲突时行为以当前需求为准。
2. 召回的偏好只能以"待确认建议"出现,确认前不得进入 RequirementState 的 must 约束或规则引擎;
   未确认的建议被静默忽略不算失败,自动变成硬约束算失败。
3. 建议呈现时必须可追溯到来源(哪次会话、什么原话、什么时间)。当前保存白名单仅有品牌、静音、尺寸、外观；
   预算、价格和规格不能经产品链路保存为偏好，相关历史事实场景只测拒绝写入。易失事实的日期与新鲜度属于未来扩展合同。

## 场景

### PM-ISO-01 本人与朋友偏好隔离
- 前置:owner 已分别显式保存 `subject=self` 的"偏好安静"和 `subject=小王` 的"偏好 ITX"。
- 输入:新会话手动选择 `self` 召回；另一会话手动选择 `小王` 召回。
- 判定维度:两次只返回对应 subject 的建议；不从会话自由文本 `recipient` 自动推断 subject。
- 负向断言:任何会话把另一 subject 的偏好当作当前需求写入。

### PM-TMP-01 临时要求不升级为长期偏好
- 前置:owner 本人偏好 A 卡;本次会话用户说"这次先试试 N 卡,就这一次"。
- 输入:数轮正常对话后开启新会话。
- 判定维度:本次会话内遵循临时要求(会话需求层 temporary);新会话召回仍是 A 卡建议;
  写入链路核对原始 scope 后,存储层不存在新的长期 N 卡记录。

### PM-CHG-01 用户更改主意
- 前置:owner 长期偏好"显卡 A 卡"。
- 输入:用户在当前会话明确说"以后都改用 N 卡了"，并显式保存该字段的当前值。
- 判定维度:存储形成 supersede 链(A 卡墓碑、N 卡 active);新会话只召回 N 卡;
  重申相同值不产生新记录。
- 负向断言:召回已 superseded 的 A 卡建议。

### PM-DEL-01 删除后不再召回
- 前置:owner 存在偏好"喜欢白色侧透机箱"。
- 输入:用户显式执行该条偏好的删除操作后开启新会话；本阶段不把聊天中的"忘掉"自动解释为删除命令。
- 判定维度:物理删除该偏好的 active 记录与全部旧值、墓碑后，任何会话不再召回该建议；
  原始会话消息的删除属于独立的会话生命周期测试。

### PM-STALE-01 旧价格/规格证据不能直接复用
- 前置:用户在会话中提及旧价格或旧规格(如"促销期整机 6999")，但当前产品保存白名单不含此类字段。
- 输入:尝试将预算、旧价格或旧规格经偏好保存入口写入，再在新会话手动召回。
- 判定维度:保存入口拒绝白名单外字段，不产生可召回记录；价格与规格仍由带日期的价格快照/目录提供，不能从偏好记忆取代数据域。
- 负向断言:保存旧价格/规格成功，或把它们当作当前可成交价/已核验规格建议返回。
- 待未来能力:若另立易失事实写入合同，再冻结 `observed_at` 与新鲜度窗口的正向场景；当前不把存储层的日期过滤能力误写成产品可保存能力。

### PM-CONF-01 召回建议须确认才生效
- 前置:owner 已显式保存稳定偏好"更喜欢 A 卡"(`brand_pref.gpu`)；历史"预算通常 1 万"不能经当前白名单保存。
- 输入:新会话明确要求 N 卡，手动召回本人偏好；另尝试保存"预算通常 1 万"后在预算 6000 的办公会话召回。
- 判定维度:当前 N 卡要求优先，历史 A 卡不得覆盖或自动进入需求；预算保存请求应被拒绝，6000 预算不受历史说法影响。
- 负向断言:未确认的 A 卡建议被写入当前需求，或白名单外预算记忆被保存/召回并拼成"6000-10000"。
