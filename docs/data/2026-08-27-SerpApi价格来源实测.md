# 2026-08-27 SerpApi 价格来源实测

> 目的：验证 SerpApi Free 下的 Baidu/Bing Shopping 是否能稳定提供中国大陆 PC 零件的结构化人民币报价。本次只运行来源 canary 和最小诊断，没有发布价格、切换目录状态、安装每日任务或调用模型。

## 1. 账户与安全门禁

- Account API 返回 `Free Plan`，初始用量为 0/250。
- 项目继续使用每月 240 次硬限制；每批执行前要求套餐、用量和剩余额度均可读取。
- Key 只保存在 Git 忽略的本机 `.env`，报告、日志和跟踪文件均不保存 Key。
- 实测结束后 Account API 返回本月用量 16、剩余 234；SerpApi 的缓存查询不计费，因此诊断请求数与用量增量不必一一相等。

## 2. Baidu Shopping canary

真实 run：`141190fa-925c-59c2-9beb-8fd228127fe4`。

固定 12 个代表 SKU 串行查询结果：

| 指标 | 结果 | 门槛 |
|---|---:|---:|
| 查询调用 | 12 | 固定 12 |
| 出现 `shopping_results` 的 SKU | 0 | 至少 10 |
| 双商家精确匹配 SKU | 0 | 至少 9 |
| 接受 observation | 0 | 必须零误匹配后才可激活 |

返回中存在普通搜索结果，部分查询存在 AI 摘要，但没有 `shopping_results` 或 `b2b_shopping_results`。这些普通结果和摘要不含完整、稳定的商家、商品链接、币种与价格条件，不能降级解释成价格 observation。

随后对同一 CPU 使用“精确型号”“价格”“购买”三种意图，并以“小米手机”作为消费品对照。四种查询仍全部返回 0 个购物结果。由此排除“只需给查询词增加购买意图”的假设。

## 3. 其他 SerpApi Shopping 引擎

- Bing Shopping 使用 `mkt=zh-CN` 查询同一 CPU：首次在本项目 20 秒超时内未完成；60 秒诊断重试返回 Success，但同时明确报告该查询没有购物结果，结构化结果数为 0。
- Google Shopping 官方支持国家列表没有中国大陆；因此没有消耗额度进行一个无法满足 CNY 中国市场约束的 canary。

## 4. 结论与裁决

SerpApi 的账户、额度和请求接口可用，但本次真实结果不能支持中国大陆 PC 零件价格自动化。问题发生在上游结果可用性，不是本项目的型号匹配器或发布器。

因此：

1. `serpapi_baidu` 和商品映射继续保持禁用/`pending_canary`。
2. 不切换 160 个现有 `active_core`，不执行 96/64 目录调整。
3. 不安装 `PCBuilderData-PriceDaily`，不开启 CatchUp 价格补跑。
4. 不把普通搜索、AI 摘要或 Bing/Google 外币结果写入 observation。
5. 现有 P12A 人工 CSV、last-known-good 和价格过期提示继续作为可用路径。

后续若更换自动价格源，必须重新满足结构化 CNY、精确型号、商家、HTTPS 商品链接、至少双商家以及两个真实轮转周期等既有门禁。不得为了完成 P12B 降低门槛。
