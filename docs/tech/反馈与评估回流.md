# 反馈与评估回流

## 最小闭环

工作台对有运行 ID 的助手回复提供“不满意”入口，用户选择原因并可填写说明。只接受自己会话内已结束的运行；相同运行只保留一份当前反馈，重复提交相同内容返回同一记录，修改内容更新反馈时间。归属检查在数据库查询中再次执行，不能仅依赖页面或 HTTP 层。

反馈保存运行 ID、原因、说明及提交时冻结的证据副本，证据哈希用作 fingerprint。反馈内容是用户判断，不等于已证实的模型错误或标准答案。证据包含当次可用的输入、输出、模型配置来源和实际保存版本；不记录 API Key、DSN、Cookie。历史运行没有捕获的证据明确标缺，不取当前需求或当前模型替代历史。

## 证据记录

产品运行在初筛与远程调用前后写入按运行和阶段区分的证据槽；每个槽首次写入后不覆盖。初筛保存有界用户消息、实际草稿/回复和配置元数据；远程构建保存提交的结构化输入、返回文本与完成版本号。配置标为 API 进程配置，不宣称它是跨进程远程 Builder 的逐请求实际模型。证据采集失败不使正常装机请求失败，但反馈导出会显示缺失。

运行终态及最终可见用户/助手消息来自数据库，反馈首次提交时一起冻结。之后的对话和需求编辑不会改变这份证据。已有反馈修改原因时沿用原证据，防止指向的场景漂移。

## 入评估集前的人工复核

`cmd/feedbackexport` 仅按明确反馈 ID 导出一份本机待复核候选，只连接指定 PostgreSQL，不调用模型或外部服务，不写正式 fixtures 或版本清单。产物放在忽略目录 `var/data/feedback-candidates/`，包含证据、用户反馈、`pending_review` 状态、空标准答案和待办字段；同名文件拒绝覆盖。

先对目标库运行 `go run ./cmd/migrate up` 并重启 API。工作台已结束回复下的“不满意”调用 `POST /api/v1/runs/{run_id}/feedback`；`GET` 同一路径读取已有反馈。请求为 `schema_version=1`、`reason` 和可选 `comment`（最多 2000 字，“其他”必填）。接口返回的 `feedback.id` 用于执行：

```sh
go run ./cmd/feedbackexport -id <反馈UUID>
```

`PG_DSN` 选择反馈所在库；导出文件尚未脱敏，只用于本机复核。`missing_evidence` 标出当前路径未捕获的阶段；历史记录不会补造证据。远程 Builder 的实际逐请求模型身份暂未回传，字段明确为 null；配置元数据不能替代这一证据。证据哈希仅标识冻结场景，不是语义去重结果。

1. 阅读原始输入与结果，判断问题属于模型、程序、数据还是评判规则。
2. 脱敏，去掉个人资料、账号信息和无关对话，再确认最小复现输入。
3. 用证据或独立人工判断确定正确行为；检查是否与现有用例重复。
4. 必要时构造少量正反例，新增用例 ID，冻结新版本；不改写旧题换取通过率。
5. 固定模型与价格快照回归，记录修复前后结果。
