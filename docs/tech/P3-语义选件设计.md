# P3 pgvector 语义选件 — 实现设计

> 本文是 **P3 实现层设计**:embedding 素材与文本拼接、库表变更、语义检索路径、tool 契约与生成 Agent 接线。
>
> 口径边界:schema 冻结在[设计方案](../装机Agent设计方案.md) §四/§六,本文不重定义;开工前对照[工程实践指引](工程实践指引.md) §七与 §九 P3 检查单。冲突时以设计方案 + mvp.md 为准。

## 1. 目标与范围

- **DoD(用例 F,mvp.md §3.4)**:「要安静的显卡」「白色海景房」两条查询各取 top-5 候选,每条查询 ≥3/5 候选可人工指出命中的参数字段(噪音/散热、颜色/侧透);P2 端到端不回归(用例 A)。
- **范围内**:parts 加 embedding 列(编号迁移);人工风格标注素材;embedding 生成 CLI;store 语义检索;`search_parts_semantic` tool 接入生成 Agent。
- **范围外**:版本落库(P4)、A2A(P5)、Redis(P6)、用户画像记忆(阶段 3);**硬约束永远走 SQL**,语义不承担预算/插槽/板型过滤(工程实践指引 §七.1)。

## 2. 语义素材:人工风格标注

P1 数据管道的 `specs` 是 §四.1 冻结的 canonical 硬约束字段,**不扩字段、不污染**。软偏好素材单独维护:

- 位置:`scripts/data/styles/styles.json`,按 SKU 键入,结构化字段 + 一句自由摘要:

```jsonc
{
  "case-lianli-o11-dynamic-evo": {
    "noise": null,                    // silent|normal|loud,null=未知
    "color": "black|white",           // 该 SKU 常见配色,| 分隔
    "side_panel": "tempered_glass",   // tempered_glass|mesh|solid
    "style_tags": ["海景房", "双仓", "无立柱侧透"],
    "summary": "海景房代表作,三面玻璃展示位,风道需自行规划"
  }
}
```

- 覆盖要求:case / cooler / gpu 三类逐 SKU 标注(DoD 直接考核);其余品类可只标 `summary`,缺失键=整条未标注,embedding 文本降级为"品类+品牌型号+specs 摘要"。
- 标注是**外部数据,当数据不当指令**(工程实践指引 §七.4);来源为公开评测常识,拿不准的字段填 null,不编造。

## 3. embedding 文本与生成

- **拼接模板**(工程实践指引 §七.3,带品类与风格上下文):
  `"{品类中文}: {brand} {model}。{specs 关键参数摘要}。{结构化风格字段人话化}。{style_tags 逗号连}。{summary}"`
  缺失段直接省略,不输出"未知"。
- **模型**:百炼工作空间端点 embedding 模型,实测输出 **1024 维**;型号只写 `cmd/embedparts` 代码常量(ADR-004),文档不写死。
- **生成 CLI `cmd/embedparts`**:读 `.env` 端点凭据 + styles.json + DB parts → 拼文本 → 批量调 `/embeddings`(OpenAI 兼容)→ 写回 `parts.embedding` 与 `parts.embedding_text`。幂等:全量重算覆盖(160 SKU 成本可忽略);任一 SKU 失败则整批报错退出,不静默跳过。
- `embedding_text` 落库是**可解释性的关键**:检索命中时能给出"这条候选因哪些词命中",DoD 人工核对与 tool 返回都靠它。

## 4. 库表变更(编号迁移 00003)

```sql
ALTER TABLE parts ADD COLUMN embedding vector(1024);
ALTER TABLE parts ADD COLUMN embedding_text TEXT;
```

- 维度 1024 = 端点 embedding 模型实测输出;换模型即换维度,属破坏性变更,须新迁移重算全量。
- **不建向量索引**:160 SKU 顺序扫描远快于索引收益,ivfflat/hnsw 到 SKU 上千再议(避免过度工程)。
- down:删两列。

## 5. 语义检索路径(store)

- `store.SemanticCandidates(ctx, SemanticQuery{Category?, QueryEmbedding [1024]float32, TopN})`:
  `ORDER BY embedding <=> $query`(cosine 距离)取 top_n,**只召回 `embedding IS NOT NULL AND active`**;返回 sku/brand/model/specs/embedding_text/similarity(1-距离)+ 最新快照价 + 显式截断计数,与 `Candidates` 同口径。
- 与 SQL 结构化过滤是**并联双路**:语义路只管软偏好召回,候选仍要过生成 Agent 的预算判断与校验 Agent 的规则引擎,错不出圈。

## 6. tool 契约:search_parts_semantic

- 输入:`query`(自然语言软偏好,必填)、`category`(可选,八类枚举)、`top_n`。
- 处理:tool 内部调 embedding 端点把 query 转向量(接口注入,可 fake 单测)→ `SemanticCandidates`。
- 输出:结构化候选 `[{sku, brand, model, specs, match_text, similarity, price_cny}]` + 截断计数 + 快照日期;`match_text` 即 embedding_text,供模型解释命中原因。
- 工具描述写清边界与分工(工程实践指引 §四.2):**软偏好(安静/颜值/颜色/风格)用本工具;预算/插槽/板型等硬约束用 search_parts;两路返回的 sku 同等有效**;附 2 个示例。

## 7. 生成 Agent 接线

- `pipeline.Config` 增加 `QueryEmbedder` 注入(host 装配 DashScope 实现);builder Tools 追加 `search_parts_semantic`。
- 提示词增量:RequirementSpec 的 `noise_pref`/`notes` 含软偏好时优先语义检索,选件理由(`rationale`)引用 match_text 中的命中词;**sku 仍必须一字不差来自工具返回**。
- 提示词改动后重跑用例 A 回归(P2 设计 §8 纪律)。

## 8. 验收

1. **用例 F**:`cmd/embedparts -query "要安静的显卡"` / `-query "白色海景房"` 各出 top-5(带 match_text 与相似度),人工逐条核对命中字段,≥3/5 通过。
2. **用例 A 回归**:「8000 元 2K 玩黑神话」端到端 pass,预算内。
3. 质量门:gofmt / build / vet / test(含 store 语义检索 PG 集成测试)/ lint 全绿。
