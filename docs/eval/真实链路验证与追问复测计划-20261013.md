## 批次 A:真实链路三合一(产品链路,非评估库)

### 前置环境

1. `docker compose up -d`(PG 15432 / Redis 16379)、`go run ./cmd/migrate up`。
2. `go run ./cmd/buildsvc`(A2 用低 `RUN_TOKEN_BUDGET` 单独起一次)。
3. `go run ./cmd/api` + SSE 客户端(curl 或 web 工作台)。
4. 正常 `.env` 模型配置;链(SCREENING/BUILDER_MODEL_CHAIN)保持为空,单模型执行。

### A1 取消级联

- 流程:建会话 → 完成需求确认 → 核定面板确认触发生成 → 生成进行中 `POST /api/v1/sessions/{session_id}/runs/{run_id}/cancel`。
- 判据(全部满足才通过):
  - SSE 依次发出 `run.cancelled` 与 `run.completed`(status=interrupted);
  - `agent_runs.status = 'interrupted'`,无 `running` 残留(`ActiveRun` 为空);
  - buildsvc 日志可见取消轮询生效(`ShouldCancel` 每轮读取 `cancel_requested_at`,F6 结论:断连不等于取消,必须显式轮询);
  - 取消后的会话可发起新消息(取消 ≠ 失败,会话不锁死)。
- 次数:2 次(生成早期取消、多轮工具后取消各 1)。

### A2 token 硬预算触发

- 流程:`RUN_TOKEN_BUDGET` 设为低于典型完成值(建议 30000,参照 runstats 历史:完整 build run 约 28 万 token)单独起 buildsvc → 正常触发生成。
- 判据:
  - 预算耗尽后进入整理轮(工具清空、注入收口指令),不是直接报错;
  - 最终 outcome 为 `proposal`(或已通过核验的 `ready`),未解决问题保留在 issues,不伪造已解决;
  - `agent_runs.status = 'succeeded'` 且 `tokens` 落库,`runstats` 可查。
- 次数:1-2 次。

### A3 无进展干预

- 触发难点如实说明:真实模型未必自然连续 3 次发完全相同的 `planning_action`;离线单测已确定性验证行为(`TestRepeatedIdenticalActionsRejectedAsStagnation`),本项验证的是真实链路上"发生时证据可见"。
- 诱导设计:给一个目录内大概率无匹配的检索目标(如要求特定小众规格词),提高模型重复同参数检索的概率;不修改任何代码。
- 判据(命中时):SSE/日志中出现 `stagnation_warning` 回喂或第 3 次拒绝执行的 error 文本;`agent_runs.tool_calls` 增量与拒绝次数一致(拒绝不耗额度)。
- 判据(未命中):如实记录"未自然触发",转长期观察——后续用 `go run ./cmd/runstats` 巡检 Top 异常 run 佐证;不得为触发而触发。
- 证据形态限制:`planning.Result` 与 `planning_artifacts` 不含完整对话轨迹,证据以 SSE 事件流与 buildsvc 日志为准;如两者均不可回查,记录该限制并考虑(另行提案)在 artifacts 中归档 FunctionResponse 摘要。
- 次数:≤2 次。

### 批次 A 预算与止损

- 上限 **60 次真实模型调用**(≤6 个 build run × ≤8 轮模型往返,加前置 Screening 会话轮次;实际预计 30-50)。
- 止损:任一 run 出现非预期 `failed`、取消后会话锁死或额度计数异常,立即停止批次并归因,不带病续跑。
