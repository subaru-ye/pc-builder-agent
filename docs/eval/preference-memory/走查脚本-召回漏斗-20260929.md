# 偏好记忆召回漏斗:小规模真实用户走查脚本与记录表(2026-09-29)

> 配套口径文档:[使用证据-召回漏斗-20260929.md](使用证据-20260929.md)。
> 用途:零真实流量下采集第一批使用证据;5–6 名真实被试(非项目成员),
> 每人 15–20 分钟,现场主持人一名。**不虚构数据**:未执行的行留空,
> 汇总表只在真实记录后填写。
>
> 安全边界(全程生效,走查不得破坏):确认前不生效、当前需求优先、冲突不代选;
> 不自动推断 subject、不自动提取、不注入模型。走查发现的产品问题只登记,
> 不现场改产品迎合被试。

## 一、环境准备(主持人,复用 20260927 走查环境,不新建设施)

1. 本机 compose:PG 15432 / Redis 16379,`AUTH_ENABLED=true` 启动 `cmd/api`
   (auth 空密钥坑见[走查记录 20260927](浏览器走查-20260927.md) 过程发现第 1 条)。
2. `web pnpm dev`(3101 端口)。每名被试独立浏览器配置文件 + 独立账号。
3. 走查前记录基线行数(复核用):

```sql
-- 只读计数,不读取 value/source 列(隐私最小口径)
SELECT 'pref_active', count(*) FROM owner_preference_memories WHERE status='active'
UNION ALL SELECT 'pref_all', count(*) FROM owner_preference_memories
UNION ALL SELECT 'edit_requests', count(*) FROM requirement_edit_requests;
```

4. 变体 S3(冲突)幕 1 由主持人按 20260927 走查第 36–40 行的构造法预置
   双身份同字段不同值;被试不参与构造。

## 二、被试与变体分配

| 变体 | 人数 | 幕 1 场景 | 幕 2 观察 |
|---|---|---|---|
| S1 本人 | 2 | 为自己配机,表达 1 条品牌偏好 + 1 条静音偏好并保存 | 默认归属(self)召回 |
| S2 具名 | 2 | 为朋友配机(自起代配名),表达偏好并保存到该归属 | 需输入/选择具名归属召回 |
| S3 冲突 | 1–2 | 主持人预置双身份冲突(如静音 安静/常规) | 冲突双选呈现与选择行为 |

## 三、主持人手册

- **幕 1(保存,约 5 分钟)**:宣读任务卡 A。任务卡只说"系统有保存长期偏好的
  功能",不指位置。若 2 分钟未找到,给标准提示①:"保存入口在会话页面里"。
  记录自发/提示后。
- **幕 2(召回,核心,约 10 分钟)**:开新会话,宣读任务卡 B(**不提任何功能名**)。
  从宣读完成开始计时到被试打开"跨会话偏好记忆"区(层级 2)。2 分钟未触达给
  标准提示②:"这个网站有跨会话偏好记忆功能"。再 2 分钟未触达,主持人演示
  打开入口,标记"演示后"。后续不再干预。
- 出声思维:幕 2 全程请被试说出想法;主持人记录**脱敏要点**(不改写原话入表,
  只记行为结论,如"以为建议会自动生效""不知道归属填什么")。
- 被试问"这些建议会自动用吗"之类时,回答口径:"你自己试,按你理解的用"——
  不解释交互设计(那正是要观察的)。

## 四、任务卡(被试视角,主持人宣读)

**任务卡 A(幕 1)**:你经常帮自己/朋友配电脑。请在对话里告诉系统你的一条
长期偏好(主持人给场景值),系统有把长期偏好保存下来的功能,请完成保存。

**任务卡 B(幕 2,S1)**:上周你在这台系统上说过自己的偏好。今天从新会话开始
配一台新电脑,把上周的想法带进来,然后继续。

**任务卡 B'(幕 2,S2/S3)**:同上,把"自己的偏好"换成"你朋友的偏好"。

## 八、判定规则(预设,引用口径文档第六节)

- 入口前移(折叠区→显式呈现):层级 2 自发率 < 50% 且提示场景仍找不到。
- 归属选择优化(历史 subject 列表化):具名被试纠错或"不知道填什么" ≥ 1/3。
- 均不满足则维持现状,证据与记录一并归档,后续复测扩样本。
- 任何改动落地后必须重跑 `cmd/evalpreference` 确定性基线(不变量回归)。
