# 价格观察与安全选价

> 人工价格 observation、选价与新鲜度已实现；自动价格来源未通过真实 canary，保持禁用。
>
> 强制规则以[数据获取与发布规则](../data/数据获取与发布规则.md)为准；实际运行命令见[价格管道 价格任务](../ops/价格任务.md)。

## 1. 目标与边界

价格管道 维护带日期的人民币参考价格，不提供实时价格、库存承诺、返佣链接或下单能力。实现分为：

- 价格基础能力：价格观察、严格人工 CSV、确定性选价、异常隔离、不可变快照和产品新鲜度提示。
- 自动价格来源：接入满足门禁的结构化人民币价格源，并完成真实 canary 和两个完整轮转周期。SerpApi/Baidu 是已实现但真实 canary 失败的候选，不再视为默认可激活来源。

当前没有启用真实自动价格来源。`serpapi_baidu` 已登记但保持 disabled，商品映射状态为 `pending_canary`；其真实 canary 为 0/12 购物结果，不能激活。京东联盟路线已放弃，ZOL 继续作为 `permission_required` 的禁用候选。普通搜索摘要、模型回答和历史 CSV 中的来源文本不能升级为正式 observation；任何后续结构化价格源也必须先通过相同 canary 和双商家门禁。

## 2. 数据模型

`price_observations` 保存不可变原始观察的结构化投影：

- `observation_id` 由 SKU、来源、商品标识、价格、观察时间和原文哈希确定性派生。
- `source_url` 必须是不含凭据的 HTTPS URL。
- 金额使用 PostgreSQL `NUMERIC(10,2)` 和十进制字符串，不使用浮点数。
- `price_type`、`stock_status` 和 `variant_match` 共同决定观察能否参与选价。
- `collector_id` 固定记录采集服务，`source_id` 表达底层商家；`availability_basis=search_listing` 明确不代表库存。
- 数据库触发器拒绝 UPDATE/DELETE；重复 ID 只在全部字段一致时幂等。

`price_snapshots` 是发布批次，增加 release、上一快照、run、manifest、policy 和 stats。`prices` 是该批次实际选中的每 SKU 报价，记录 observation、实际观察时间、价格类型、是否沿用以及真正来源快照。

历史 `2026-07-28` 四列 CSV 被回填为 `bootstrap/legacy`：保留金额和日期，但不伪造 URL、商品标识或已验证 observation。

## 3. 价格管道 CSV 契约

固定表头如下，顺序不可变化：

```text
sku,price_cny,currency,source_id,product_id,source_url,seller,price_type,stock_status,variant_match,observed_at,raw_sha256
```

字段规则：

- `sku` 必须属于当前 `active_core`。
- `currency` 只允许 `CNY`；`price_cny` 为正十进制且最多两位小数。
- `observed_at` 为带时区 RFC 3339，不能位于未来。
- `raw_sha256` 是操作者核验时所依据原始内容的 SHA-256，不保存完整受限页面。
- `regular/sale` 可参与选择；`coupon/member/msrp` 只保留观察；订金、月供、搭售和未知类型拒绝。
- 只有 `in_stock + exact` 可参与选择；缺货和未知/不匹配变体拒绝。

旧的 `sku,price_cny,source,captured_at` 仍可由 `cmd/importprices` 导入，目的仅是历史兼容，不能产生 价格管道 证据。

## 4. 确定性选择

每个 SKU 独立执行：

1. 过滤非 `active_core`、非 CNY、非精确变体、非在售或不合格价格类型。
2. 三个及以上不同合格来源时，计算十进制中位数，选择与中位数距离最近的实际报价。
3. 一至两个来源时按登记优先级选择。
4. 并列依次按来源优先级、价格类型、观察时间、金额和 observation ID 排序。
5. 新选价相对上一选中价变化超过 25% 时隔离该 SKU，并沿用上一正式值。

批次异常数达到 `max(3, ceil(本批合格 SKU 数 × 10%))` 时隔离整批。没有安全变化时返回 `no_change`，不制造新快照。

价格基础能力 使用逐 SKU 合并：安全新价替换，其余 SKU 沿用 last-known-good，并保留旧观察日期。这样部分更新不会把未覆盖 SKU 误删，也不会把“今天发布”伪装成“今天观察”。

## 5. Release 与原子发布

价格使用独立 price release v1，不修改 数据管道 parts release v1/v2。每个 release 固定包含：

- `observations.jsonl`
- `selection.jsonl`
- `review.json`
- `manifest.json`

manifest 保存各文件哈希、联合输入哈希、上一 release、run、快照日期、policy 和统计。Go 导入器重新校验路径边界、大小、SHA-256、UUID、JSON 尾部和 manifest 哈希，然后在同一 PostgreSQL 事务中写入 run、observations、snapshot 和 prices。

同 manifest 重试返回同一 release；同一日期不同 manifest 失败。数据库成功后才原子切换 `var/data/current-price.json`。价格主链和普通测试的模型调用数固定为 0。

## 6. 动态新鲜度

新鲜度不固化进 build，而是在读取历史 build 时根据其保存的快照和逐 SKU `observed_at` 动态计算：

| 状态 | 年龄 | 产品行为 |
|---|---:|---|
| `fresh` | 0–7 天 | 明确“参考价、非实时价” |
| `aging` | 8–14 天 | 琥珀色提示“价格可能已变化” |
| `stale` | >14 天 | 红色提示“价格快照已过期” |
| `unknown` | 缺价或无法关联 | 提示重新核价，不伪造观察日期 |

`PartLine` 可返回 `price_observed_date` 和 `price_freshness`；`Quote` 返回最早观察日期、最大年龄和四种计数；`BuildSummary` 返回整体状态。变更为向后兼容可选字段，不新增路由，不修改 Agent/A2A schema。

过期价格不会把硬件兼容性改成 fail，也不会让 `/readyz` 失败。配置仍可生成，但工作台、公开分享页和 Markdown 必须强提醒购买前核价。

## 7. 自动价格来源 来源门禁

首个实现使用 SerpApi 的[官方 Account API](https://serpapi.com/account-api)和[Baidu Shopping Results API](https://serpapi.com/baidu-shopping-results)，不直接访问商城页面。[Free 套餐](https://serpapi.com/pricing)为每月 250 次，项目硬限制 240 次；每批先免费查询 Account API，不是 Free、额度不可读、预计超限、401/403/429 时立即停止。

12 SKU canary 固定使用版本化映射，要求至少 10 个出现购物结果、至少 9 个得到两个独立商家/目标主机的精确匹配，并人工确认接受结果零误匹配。通过前不得：

- 把 `serpapi_baidu` 或映射的 `activation_status` 改为 active。
- 把目录从 160 个 `active_core` 改成 96/64。
- 启用每日自动采集调度。

2026-08-27 的真实 canary 未满足第一项门槛，Baidu 的购买意图查询和消费品对照也没有购物结果；Bing Shopping `zh-CN` 同样无结果，Google Shopping 不支持中国大陆市场。实测过程见[SerpApi 价格来源实测](../data/数据来源决策.md)。这些失败不会降低 自动价格来源 的验收标准。

通过后每批处理 7 个最久未尝试 SKU，约 14 天覆盖 96 个核心 SKU。搜索报价统一为 `price_type=listing`、`stock_status=unknown`、`availability_basis=search_listing`；至少两个独立商家或目标主机才参与中位数实际报价选择。

一般自动适配器启用前仍必须同时满足：

- 条款与 robots 明确允许低频自动访问，并记录审核日期和内容哈希。
- 不需要登录、Cookie、验证码、代理、账户签名或地区绕过。
- 使用固定 SKU→具体商品映射，不做全站搜索或新品发现。
- 能确定性识别型号、变体、库存、正常售价和优惠类型。
- 支持条件请求或内容哈希；跨主机重定向、401/403/429 和结构变化立即隔离。

自动价格来源 完成还要求所有 `active_core` 正式选价最大年龄 ≤14 天、平均 ≤7 天，自动来源覆盖全部正式选价，并连续两个 14 天轮转周期产生安全发布或确定性 no-change。人工 CSV 是恢复通道，不计作全自动覆盖。

## 8. 兼容性

- `RequirementSpec`、`ChangeRequest`、`BuildDraft`、`ValidationReport`、A2A 和 `cmd/builds` 参数保持不变。
- 历史 build 的金额与快照保持不可变；只有“距今天数”动态变化。
- `cmd/importprices` 继续接受旧四列 CSV。
- 数据管道 规格发布与价格发布互不回滚；价格批次错误只把该 run 标为 `partial` 并保持 last-known-good。
