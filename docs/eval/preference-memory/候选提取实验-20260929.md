# 长期偏好候选离线实验（暂定金标）

基于 `main@ab9258b`。本实验只在 `planningeval` 与 `cmd/evalpreference` 内运行，
没有产品接入、数据库读写或模型调用。目标是判断已经结构化的当前需求是否值得
向用户提出“是否长期保存”的候选。候选不是保存授权，归属始终为
`requires_user_selection`，不填写 `self`，不读取 `recipient` 推断身份。

## 输入、策略与边界

- 输入为合成消息及固定 `RequirementOperation`，经真实 `ApplyRequirementUpdate`
  形成最终 `RequirementState`。字段值、强度、来源沿用上游结果；本轮不测自然语言
  到字段值的提取能力，不测 `StartMessage` 或生产提案授权。
- `eligibility-v0` 是对照：复用稳定字段白名单、active/session、证据类型、真实消息
  中 quote 子串、来源 role、字段取值与强度校验，不判定长期意图。这不是当前产品的
  自动保存策略；当前产品还有用户主动点击保存的授权。
- `lifetime-v1.1` 在相同结构准入上增加语言护栏：在字段原话的同一分句寻找持续意图
  与值锚点，结合完整来源消息拦截部分临时、否定、条件、疑问及转述表达。
  `scope=session` 本身不会产生长期候选。
- `accepted_proposal` 的文字标签不能证明提案已实际展示并被接受。本实验不复制
  产品授权器，两条策略都给 `proposal_needs_product_verification` 弃权；暂定金标
  中上下文明确的接受仍作为正例计 FN，从而暴露上下文接入缺口。
- 只处理最终状态。撤销、冲突、temporary（包括其 Previous）不输出；新的普通
  改口不会继承旧值的长期词。对后续不更新字段的记忆意愿变化存在已知检测上限。
- 输出逐字段 reason 与候选，保留值、strength、evidence、session/message/quote。
  候选值复制后返回，不修改输入状态，不产生记忆或需求写入。

## 语料与暂定金标

语料为本次助手编写的合成数据，未读取主库或私人对话：

- `internal/planningeval/testdata/preference-candidates/dev.json`：24 条开发样本。
- `internal/planningeval/testdata/preference-candidates/validation.json`：29 条分组验证样本。
- 每条包含 `family/category/turns/expected/rationale`。固定操作只是上游夹具，
  `expected` 是逐题选择的候选及其值、强度和原话来源，不从策略运行结果生成。
- `inferred` 或伪造 quote 的负例显式标注 `expect_rejected`，真实 Reducer 必须拒绝；
  其他夹具被拒绝算技术错误，不能被计成“正确地没有候选”。
- family 不能跨集合，ID 不能重复；这只是数据组织检查。规则和两组数据均由同一
  助手编写，**不是盲测，不是独立人工验证**，所有自然语言金标状态均为 `provisional`。
  特别需要复核历史时态、跨分句作用域、长期无偏好、提案接受四类标注。

## 运行与计分

```bash
go run ./cmd/evalpreference -mode candidate-check
go run ./cmd/evalpreference -mode candidate-run -split dev -out artifacts/preference-memory/candidate-20260929/dev-v1.1
go run ./cmd/evalpreference -mode candidate-run -split validation -out artifacts/preference-memory/candidate-20260929/validation-v1.1
```

复跑请换新的 `-out`，已有目录拒绝覆盖。默认 `-split dev`，可显式选 validation/all。
不需要 DSN、Docker 或 API key。产物 `report.json` 含每条决定、错误及指标，
`report.md` 先列 FP 再列 FN。退出码 0 代表实验执行成功，不代表候选策略通过生产门禁。

Precision = TP/(TP+FP)，Recall = TP/(TP+FN)，按候选字段精确计数；值、强度、
evidence 或原话来源错误同时计 FP 与 FN，归属状态必须等待用户选择。零分母为 null，
不显示成 100%。另报整例全对数；没有候选的负例不会抬高候选级 Precision。

报告保存规则文件与两组语料的 SHA256（规范化 CRLF 为 LF）；上游 Reducer 和已有
通用 helper 的版本以 Git 提交为准，规则文件 hash 不代表整仓代码 hash。

## 决定与后续

当前候选策略不能进入产品设计实施阶段。它在这组合成暂定金标上相较结构准入
对照减少了误提取，但仍存在用户明确撤回意愿后的候选；同时 Recall 明显下降。
这些数字不能表述为线上收益、模型效果或真实用户接受率。

下一步先复核暂定金标中的作用域和持续性定义，再决定是否为已验证的产品提案
提供只读授权上下文。若继续策略实验，应另收新样本并固定规则后运行；当前验证集
已经暴露，可作为回归集，不再作为后续独立验证集。现有显式保存/召回功能不受影响。
