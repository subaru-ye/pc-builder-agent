## 通用判定原则（对所有场景生效，非金标）

1. 用户确认的当前需求永远高于历史记忆;两者冲突时行为以当前需求为准。
2. 召回的偏好只能以"待确认建议"出现,确认前不得进入 RequirementState 的 must 约束或规则引擎;
   未确认的建议被静默忽略不算失败,自动变成硬约束算失败。
3. 建议呈现时必须可追溯到来源(哪次会话、什么原话、什么时间);旧价格/旧规格证据必须带日期且不得作为现状陈述。

## 场景

### PM-ISO-01 本人与朋友偏好隔离
- 前置:owner 既有"本人偏好安静"又有"给朋友小王配机偏好 ITX"。
- 输入:新会话"帮我配一台";另一会话"帮小王配一台"。
- 判定维度:两条线各只召回对应 subject 的建议;本人会话不出现朋友的 ITX 建议,反之亦然。
- 负向断言:任何会话把另一 subject 的偏好当作当前需求写入。

### PM-TMP-01 临时要求不升级为长期偏好
- 前置:owner 本人偏好 A 卡;本次会话用户说"这次先试试 N 卡,就这一次"。
- 输入:数轮正常对话后开启新会话。
- 判定维度:本次会话内遵循临时要求(会话需求层 temporary);新会话召回仍是 A 卡建议;
  写入链路核对原始 scope 后,存储层不存在新的长期 N 卡记录。

### PM-CHG-01 用户更改主意
- 前置:owner 长期偏好"显卡 A 卡"。
- 输入:用户明确说"以后都改用 N 卡了"。
- 判定维度:存储形成 supersede 链(A 卡墓碑、N 卡 active);新会话只召回 N 卡;
  重申相同值不产生新记录。
- 负向断言:召回已 superseded 的 A 卡建议。

### PM-DEL-01 删除后不再召回
- 前置:owner 存在偏好"喜欢白色侧透机箱"。
- 输入:用户要求"忘掉这条偏好"后开启新会话。
- 判定维度:物理删除该偏好的 active 记录与全部旧值、墓碑后，任何会话不再召回该建议；
  原始会话消息的删除属于独立的会话生命周期测试。

### PM-STALE-01 旧价格/规格证据不能直接复用
- 前置:记忆中存在带 observed_at 的易失事实(如"促销期整机 6999",观察日期远早于当前)。
- 输入:新会话询问整机价格/推荐。
- 判定维度:超出新鲜度窗口的易失记忆不进入建议;若提及历史价格必须标注观察日期并引导重新确认;
  价格与规格真值仍以带日期的价格快照/目录为准,记忆不得绕过数据域。
- 负向断言:把旧价格当作当前可成交价陈述,或未经日期标注直接复用旧规格证据。

### PM-CONF-01 召回建议须确认才生效
- 前置:owner 存在稳定偏好"预算通常 1 万"。
- 输入:新会话直接说"配一台 6000 的办公机"。
- 判定维度:当前需求(6000/办公)完全生效;历史预算建议至多以可追溯建议形式出现,
  不得覆盖、稀释或与当前需求拼接成"6000-10000"之类的未确认约束。
