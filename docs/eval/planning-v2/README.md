# 当前产品链路的离线评估

**2026-09-15 当前默认入口已切到 123 件目录的 10 个机制场景**，结果与调用消耗见[当前目录有限验收](current-123-20260915.md)。20 题 Screening 录制、1 题散热失败录制、本次 CPU 录制及历史 50 题迁移由 `internal/planningeval/testdata/current-123-20260915-r2/index.json` 统一索引。下文 12 题仍是独立的历史固定目录机制回归，显式传入其 suite 可运行。

当前业务收尾以[有限验收](业务收尾有限验收-20260915.md)为准：复用以下机制、录制与浏览器测试，不再以追平历史分数作为交付条件。

离线模式验证机制是否正确执行，不读取正在更新的 `scripts/data`，不重启产品服务，不调用真实模型、Embedding 或联网服务。默认使用专用数据库容器；显式 `--local-postgres` 可在既有本地服务中创建全新独立测试数据库，仍不读写业务库。

2026-09-15新增[冻结数据对比回放](data-pair-20260915.md)：旧160件目录和新172件目录分别运行相同输入及协议响应，验证实际检索、缺价与交付变化。该套件独立于以下12个机制场景，不合并为模型成功率。

另有[自由需求与工具失败回放](behavior-20260915.md)，覆盖未知预算、多条自由条件、已有件简称、语义检索和网页不可用后继续规划，共3个独立场景；使用相同的172件冻结目录。

旧 v1.5 的 50 个场景和历史分数保留。[逐题审查](legacy-audit.md)与[机器可读审查](legacy-audit.json)记录当时的迁移需求；随后已分别迁入 19 题 Screening 和 31 题 Builder 套件，位置见当前索引。这不表示全部 50 题已在当前目录真实跑通；下文 12 题是单独登记的机制场景。

## 执行什么

`cmd/evalplanning` → `product.Service` → 真实 Screening 提示和 ADK 协议 → 服务端需求更新 → 需求确认或继续改单 → `planning.Runner` 工具循环 → 本地结构化检索、报价、兼容性核验 → A2A 结果编码/解码 → 正式版本事务及产品读取模型。

每次运行由 `scripts/eval/planning/run.py` 创建专用 PostgreSQL 容器，执行当前迁移，导入固定测试样本。运行结束删除本轮容器；只接受 localhost 上 `peval_` 开头且空的数据库。CLI 不读取 `.env`、`DATABASE_URL` 或 `PG_TEST_DSN`。网页和搜索通过只接受登记 URL 的内存 transport 返回冻结资料，未登记请求直接失败，不回退真实网络。

使用的是实际业务代码，模型输出则是明确标注的人工协议响应。P2-005 的最终 Builder 输出直接取自保存记录；其他场景的模型操作序列是根据真实问题构造的回归 oracle。它们用于验证“模型作出这些决定后，系统是否正确执行”，不能证明模型会自行作出正确决定。实际输入和工具反馈完整保留，可据此检查需求与配置是否送到了模型。

隔离目录包含 8 件保存方案配件、1 件保存升级配件和1件明确标注的插槽冲突测试件；并非用于测量市场覆盖率的小型替代商品库。原始记录、人工变动及哈希见 `internal/planningeval/testdata/provenance.json`。运行前验证套件原始字节哈希，避免悄悄变更基线。

## 场景与断言

| 编号 | 场景 | 核心验证 |
| --- | --- | --- |
| P2-001 | 预算充足，升级 CPU，其他配件尽量不动 | 同轮进入 Builder、执行检索与校验、保留其他件、旧版不变、重试幂等 |
| P2-002 | 为朋友装机，预算修改、撤销、备选和临时例外 | 其他偏好保留、撤销不复活、备选不覆盖、同用户新会话不继承 |
| P2-003 | 2K 素材改为 1080p | 稳定自由条目更新、重复 notes 撤销、显示分辨率仍未知 |
| P2-004 | 6000 元剪辑，必须静音后改为尽量静音 | must 进入模型和检索、有具体候选及缺证据原因、转 prefer 后继续交付 |
| P2-005 | 保存的 proposal，问题为空且检查完整 | 服务端自动交付，重复请求只产生一个正式版本 |
| P2-006 | 外部 5900X 规格注册 | 搜索线索与正文来源分开、规格进入候选、外部价格不采信、缺价与关键未知保留为问题 |
| P2-007 | 用户请求查价格 | 以本地报价运行，不调用在线搜索或网页读取 |
| P2-008 | 未知预算和游戏显示目标 | 允许讨论，未表达字段不变成默认偏好 |
| P2-009 | 面板改预算与聊天改预算 | 相同服务端字段语义，其他偏好保留，刷新恢复 |
| P2-010 | 正式配置后的备选讨论 | 不误执行、不修改当前要求与正式版本 |
| P2-011 | 模型声称 ready，但 CPU/主板真实冲突 | 服务端不伪装通过，反馈后保留有具体问题的候选 |
| P2-012 | 收到真实插槽失败后重新选件 | 失败工具结果实际进入模型输入，重新检索、校验后交付 |

评分同时检查字段值、状态、强度、来源、Builder 实际输入、工具请求与执行记录、报价、校验、候选事实、版本数量和历史快照。预设型号只用于固定回放回归；未来真实模型评分应接受其他同样满足需求的方案。

运行分类包含交付、带证据的待解决、澄清、收集、面板编辑、读取/重试、停滞和故障。待解决需要候选、问题以及事先审查的具体问题断言；任意借口或空问题 proposal 不算通过。刷新旧配置不增加交付次数。重复追问当前使用用例级禁止片段检查，尚不是通用语义判分器。

## 运行与产物

在项目根目录，通过 Git Bash 执行：

```bash
# 仅审查旧题与验证新套件；不启动服务
python scripts/eval/planning/audit_legacy.py
go run ./cmd/evalplanning -mode check

# 无数据库的评分器、隔离边界和协议反向测试
go test ./internal/planningeval ./cmd/evalplanning

# 真实产品服务 + 专用临时数据库；输出目录必须不存在
python scripts/eval/planning/run.py --out artifacts/planning-eval-new
```

需要本机 Go、Python、Docker 和 `pgvector/pgvector:pg16` 镜像；首次无镜像时 Docker 可能下载镜像，但不会调用模型或商品资料服务。不要将共享库连接传给入口。生成器 `build_fixture.py` 仅用于显式修订套件，普通评估不重建 fixture。

输出包括 `report.json`、当次 `suite.json`、`provenance.json` 和 `manifest.json`。报告逐轮保存真实输入、模型响应、工具反馈、最终状态、断言、耗时；清单保存 Git HEAD、可执行文件/代码/迁移哈希和容器镜像 ID。工作区有未提交改动时，不能只凭 HEAD 复现，须保留对应代码。原始产物位于忽略目录，审查结论和可重放输入在源码中保留。

用量口径：`screening_calls` / `builder_calls` 是协议调用数；`actual_model_requests` 是已尝试的提供方调用数（失败也计入，不能等同于计费成功次数）；`search_calls` / `page_calls` 是工具层逻辑次数；`external_requests` 是真正的资料联网次数，不含模型端点。离线模式可出现1次搜索工具执行但0次联网。每轮 `duration_ms`、模型Trace耗时与Builder `stage_ms` 用于定位开销。离线Token和金额为null，不伪装成真实推理零成本。

## 显式真实模型模式

`plan-live`仅校验冻结套件和本机模型配置并生成计划，零数据库/模型调用；`live`通过相同产品与工具路径调用真实Screening/Builder，网页仍为冻结回放，Embedding不启用。真实套件必须标记 `live:true`，禁止含oracle；模型配置须与指定的脱敏基线完全一致，禁止模型链及SDK自动重试。总调用上限跨角色共享，超过上限的尝试不发送给提供方，失败和后续未完成场景仍保留在分母。

```bash
go run ./cmd/evalplanning -mode plan-live -suite internal/planningeval/testdata/live-smoke-20260915/suite.json -out artifacts/live-plan-new -max-calls 12
python scripts/eval/planning/run.py --live --suite internal/planningeval/testdata/live-smoke-20260915/suite.json --out artifacts/live-smoke-new --max-calls 12
```

每个输出目录只能使用一次；不自动重跑失败批次。CLI在调用前保存plan、suite与provenance；events.jsonl逐次同步保存请求前记录、原始响应和每步产品结果，包含输入/输出/总token。中断时以journal为证据，不因缺最终report而重置额度。计划保存模型配置、完整目录/套件/二进制哈希；启动器另存源码/镜像身份。凭据不进入报告。这里的测试文本是已登记的合成场景，不应把真人私人对话直接写入这些完整轨迹。

首批只有预算修改及8000元2K游戏生成，不代表历史50题或CPU升级等场景已跑完。要求完整报价、真实兼容性通过、预算不超上限和正式版本关联，不固定具体SKU或模型轮数。真实模型效果须以实际报告为准。

本轮结果见[验收记录](validation-20260914.md)。没有浏览器验证、真实模型效果、外网读取质量或生产容量结论。A2A 仅验证结构化结果编解码，未验证 HTTP 传输及远端会话故障；语义检索/Embedding 质量也不在本轮覆盖内。

## 数据更新完成后

先冻结商品、规格、证据、价格及采集时间，记录各自哈希，创建新评估版本，避免在跑测时读取不断变化的 active 数据。数据任务不需要等待本套件，也不应为让测试通过而修改采集判断。

建议以相同当前代码、相同模型与额度，分别跑旧数据快照和新数据快照，比较候选覆盖、报价完整度、关键规格缺失、交付率、待解决原因、检索次数、耗时和实际用量。这才能归因于数据补充。机制变化则在固定数据上单独比较；旧执行器历史分数与新 planning 分数不可直接混成同一排行榜。

继续补充目录缺失、非预设用途、多自由条件、外部来源冲突、执行中需求变化等场景，并将冻结网页回放与小规模真实联网冒烟分开。预留未参与补数据挑选和提示调优的保留题，防止只针对已知失败提高分数。本轮未启用新增真实模型或外部服务消耗。

已冻结的目录可通过 `scripts/eval/planning/build_snapshot_pair.py` 转换为独立套件；入口要求输入哈希和明确的价格快照ID，不读取实时数据库、不过期价回退。实际检索断言关联模型调用编号与下一次输入中的工具返回，不把初始目录、模型回复或搜索错误当作检索证据。报价原观察时间、类型、来源和可用性依据随套件保留；完整来源关系及运行边界见上述对比记录。
