# 装机配置单 Agent — 阶段 1 实现指导

> 状态:规划冻结;P7–P9 已实现,P10 的自动门禁与 Live Pass³ 已通过,真人盲评待完成。本文是 MVP P0–P6 封板后,阶段 1(P7–P10)的短期执行唯一依据。
>
> 当前待封口工作、阻塞原因和恢复步骤集中记录在 [阶段 1 待封口 Backlog](stage1-backlog.md)。

## 0. 文档定位

本文把 PRD 的「阶段 1 · 可分享的可信配置单」裁成可逐段实施、逐段验收的工程计划。长期产品方向仍以 PRD 为准;四份核心 Agent schema、兼容性规则和 A2A 契约仍以设计方案为准;各阶段的具体实现细节见 P7–P10 专题文档。

发生冲突时按以下优先级处理:

1. 产品范围与阶段退出标准:本文。
2. RequirementSpec、ChangeRequest、BuildDraft、ValidationReport 与规则语义:设计方案。
3. 产品 API 与 SSE:OpenAPI 和 SSE 事件协议。
4. 具体技术实现:P7–P10 专题设计。

阶段 1 不修改 mvp-freeze 标签,也不回写或重解释已经通过的 P0–P6 验收结果。

## 1. 一句话目标

在不改变现有 Agent、A2A 和规则契约的前提下,把已经可演示的后端能力包装成一个本地可完整使用、未来可部署的匿名 Web 产品:用户先确认需求,再生成配置,随后可改单、回看版本、比较差异并分享只读结果。

## 2. 目标用户与成功路径

阶段 1 面向两类用户:

- 想快速得到可信配置单、但不熟悉兼容规则的普通装机用户。
- 帮朋友配机器、需要解释理由、展示校验和对比版本的进阶用户。

标准成功路径固定为:

1. 用户输入「8000 元,2K 玩黑神话」等自然语言需求。
2. 初筛 Agent 追问真正缺失的关键字段。
3. Web 展示结构化需求单;用户可编辑并明确确认。
4. 系统异步生成、校验并保存 v1,全程展示真实进度。
5. 用户通过自然语言或零件行快捷入口发起改单,生成 v2/v3。
6. 用户回看旧版本、选择任意两版 diff、导出 Markdown。
7. 用户创建只读分享链接或分享图;本地地址明确标注访问范围。

## 3. 范围裁定

### 3.1 范围内

- Go 产品 API,匿名身份、产品会话、稳定聊天记录和长任务状态。
- 需求收集、需求确认卡、严格 schema 编辑与确认后生成。
- Next.js Web 工作台,桌面双栏和手机可用布局。
- 当前配置、12 条校验、报价快照、版本回看和任意两版 diff。
- Markdown 导出、分享图、可撤销只读分享链接。
- Redis SSE 重放和会话恢复;Redis 故障时的显式降级状态。
- golden set 从 20 组扩至至少 50 组。
- 3–5 位真人端到端测试和「可直接照买」盲评。
- 本地完整运行与公网部署准备清单。

### 3.2 范围外

| 项目 | 去向 | 本阶段不做的理由 |
|---|---|---|
| 邮箱、OAuth、账号与角色权限 | 后续产品化议题 | 匿名身份已足够验证核心体验 |
| 正式域名、云服务器与生产 SLA | 可选发布关卡 | 当前没有基础设施,不让部署阻塞本地产品 |
| 京东等电商实时价格 | 阶段 2 | 继续坚持带日期的离线快照 |
| 自动价格更新与 SKU 扩容 | 阶段 2 | 数据工程独立推进 |
| Intel/LGA1851 平台 | 阶段 3 | 当前仍为 AM5 单平台 |
| 跨会话长期偏好画像 | 阶段 3 | 匿名 cookie 只承担隔离,不等于画像 |
| 商品图片 | 数据资产专项 | 当前没有来源、版权和稳定 URL 契约 |
| 多实例任务调度与高可用 | 正式部署前 | 阶段 1 只承诺单 API 进程 |

### 3.3 范围变更纪律

- 新功能先进入 PRD backlog,不得插入正在实施的 P7–P10。
- 任何变更不得绕过 12 条规则或把 LLM 自评当作最终结论。
- 前端快捷操作只能生成可编辑的自然语言改单草稿,不得产生第二套改单协议。
- Next.js 不承载业务规则;所有业务写操作进入 Go API。

## 5. 分阶段工作包

### 5.1 P7 产品 API 与状态机

1. 抽取 host Agent 装配,保持 cmd/host 行为不变。
2. 建立产品表与 store,把匿名归属、产品消息和运行记录持久化。
3. 完成会话 CRUD 的读取面和所有权校验。
4. 将初筛和远程生成拆成明确的确认关卡。
5. 建立后台 run、Redis 事件流、SSE 重放、幂等与单会话互斥。
6. 将 builds、diff、Markdown presenter 抽成 CLI/API 共用确定性代码。
7. 完成 OpenAPI、handler 单测、PG/Redis 集成测试和真实 A2A 回归。

推荐提交粒度:

- P7 文档与 OpenAPI 契约。
- host 装配抽取,行为零变化。
- web_sessions/web_messages/agent_runs 数据层。
- 需求确认状态机和 run 执行器。
- SSE 与恢复。
- build read model、diff、export。

### 5.2 P8 Web 工作台

1. 初始化 web 工程、设计 token、基础布局和 API 类型生成。
2. 完成匿名会话入口、会话列表和聊天历史。
3. 完成需求确认卡和 schema 校验反馈。
4. 接入后台 run 与 SSE,展示真实进度、断线和重连状态。
5. 完成配置、校验和版本检查器。
6. 完成自然语言改单快捷入口和 diff。
7. 完成移动布局、无障碍、错误/空/加载状态。

推荐提交粒度:

- Web scaffold 与设计上下文。
- App shell 与 API client。
- 对话/需求确认。
- 配置/校验。
- 版本/diff。
- 响应式与无障碍收口。

### 5.3 P9 分享与导出

1. 抽取并锁定共享 presenter。
2. 实现分享 token 创建、读取、撤销和所有权校验。
3. 完成只读分享页 SSR。
4. 完成 Markdown 下载和 ImageResponse 分享图。
5. 增加 localhost/局域网范围提示和公网安全清单。

实现结果:P7 已抽取的 `internal/presenter` 被 CLI、所有者导出和公开导出共用;P9 新增带独立密钥的 HMAC token、哈希存储、所有者分享管理、SSR 只读页与 1200×630 PNG。使用现有 v3 的真实验收未调用大模型,跨 API 重启幂等、无 Cookie 读取、越权拒绝和撤销即时失效均通过。

### 5.4 P10 评测与发布准备

1. 扩展规则 golden set 至至少 50 组。
2. 建立前端单测、组件测试、mock E2E 和真实 Agent E2E 分层。
3. 固定 3 次连续 LLM 回归用例,记录耗时和失败。
4. 用统一 rubric 完成 3–5 人盲评。
5. 修复发现的问题,再次跑全量门禁。
6. 更新 README 演示说明,创建阶段 1 完成提交与标签;标签名称在实现完成前不预占。

实施检查点(2026-08-10):50 组 golden、Go/PostgreSQL/Redis/Web/Python 自动门禁、Live 结构化记录器、报告校验器和真人验收模板已落地。真实矩阵运行暴露并修复预算窗口、需求缺省值展开、可消除 unknown 重试、预算改单最少变更和 Live 终态读写竞态等问题。切换到仍有免费额度的 `qwen3.7-max-2026-05-20` 后,L1–L6×3 以 18/18 通过,脱敏结果见 [P10-Live 验收汇总](../acceptance/P10-Live验收汇总.json)。真人样本仍为 0/3,所以本阶段未退出,也未创建 `stage1-freeze`。

优化检查点(2026-08-12):已新增百炼、MiMo 和通用 Responses 供应商层，三个模型角色可独立配置且禁止自动 fallback；产品初筛上下文限制为同类最近 6 条/4000 字，明确 A/N 卡改单不调用初筛，builder 只保留 Loop 的确定性最终校验。旧的 18/18 结果仅作为优化前历史基线；优化后的完整 Pass³ 与真人盲评仍是阶段退出条件，详见 [ADR-007](../tech/ADR-007-模型供应商适配与成本控制.md)。

## 6. 阶段 1 退出标准

### 6.1 机器门禁

- Go 单元、PostgreSQL、Redis 集成测试无跳过。
- go vet 与 golangci-lint 无新增问题。
- Python 数据流水线 104 项基线测试继续通过。
- Web lint、typecheck、unit、Playwright E2E 全绿。
- OpenAPI 与实际路由一致,生成的 Go/TypeScript 类型无未提交差异。
- golden set ≥50;错误级 100%,含警告级整体 ≥95%。
- 用例「初始配置→降 500→换 A 卡」连续运行 3 次,版本锁定和最终校验均正确。
- 匿名用户之间无法读取会话、版本或撤销对方分享。

### 6.2 体验门禁

- 首个真实进度事件 ≤1 秒;15 秒内至少有心跳或进度。
- 超过 60 秒时明确展示长任务状态;10 分钟硬超时后给出可恢复错误。
- 375px、768px、1440px 三档视口无关键功能缺失。
- 状态不只靠颜色表达;键盘可完成需求确认、发送、版本切换和导出。
- 3–5 位真人各完成一次完整路径,「可直接照买」盲评可用率 ≥80%。
