# 系统架构

> 当前产品规划链路、候选证据快照与方案存储见[自主规划流程](自主规划流程.md)。默认入口已改为 planning；旧 Harness 结构用于显式历史诊断。

> 更新：2026-09-07。本文说明当前模块边界与技术约束。产品需求见[PRD](../product/PRD.md)，待办见[路线图](../product/路线图.md)，栈级决策见[技术选型](技术选型.md)。接口与字段以代码、OpenAPI 和数据库迁移为准，不维护另一套示意 JSON 真值。

## 一、产品边界

对话收集需求，生成经过规则校验、绑定价格快照的配置单，支持增量改单、版本对比、分享与导出。价格是参考快照，不承诺实时成交价；BIOS、QVL 等边界随产品报告展示。

## 二、用户流程

用户输入 → 初筛追问或结构化需求 → 用户编辑确认 → 生成与确定性校验 → 保存不可变版本 → 改单、对比、分享与导出。API 与 Web 管理产品状态。

## 三、Agent 与服务

产品真实运行形态(`BUILD_HARNESS_MODE=planning`):**2 个 LLM Agent + 零 LLM 校验节点 + 有界工具循环**,控制流由产品状态机写死。

```text
Web → Go 产品 API(状态机:初筛 → 需求核验 → 规划)
                         ↓ 单跳 A2A(控制面;重载荷按 run 归档 PG)
                    buildsvc: planning.Runner(≤8 轮,planning_action 元工具)
                         ↓ search_local / read_page / read_evidence / evaluate
             rules 引擎 12 条 + int64 分报价(零 LLM),核验结果回喂
                         ↓ finalize 只能降级 + deliveryGate
        产品侧零 LLM 复验一致 → CompletePlanningRun 事务:版本 + proposal
```

- 初筛负责文本意图、缺失信息追问与结构化需求；明确改单可走程序解析。
- 历史执行器 v2/legacy(`BUILD_HARNESS_MODE` 显式设置)仅供评估,是显式历史诊断路径;产品 HTTP 入口不可用,失败不会自动切换。
- [A2A 服务边界、Redis 会话与版本快照](服务与状态.md)保持单跳,循环留在 buildsvc,跨进程只传结构化控制面数据。
- 模型角色独立配置。当前 `.env.example` 使用 Builder `qwen3.8-max-0902`、Screening `deepseek-v4-flash-0731`，二者固定且关闭额度链；Embedding 保持 `qwen3.7-text-embedding`。具体部署以环境配置为准。

## 五、兼容性规则表(校验 Agent 初版)

规则 ID 于 2026-07-28 随 P1 契约冻结,执行顺序 = 表内顺序:

| # | 规则 ID | 规则 | 级别 |
|---|---|---|---|
| 1 | `SOCKET_MATCH` | CPU 插槽 == 主板插槽(AM5/LGA1851) | 错误 |
| 2 | `CHIPSET_SUPPORT` | 主板芯片组 ∈ CPU 支持列表 | 错误 |
| 3 | `MEMORY_GENERATION` | 内存代数(DDR5)== 主板支持 | 错误 |
| 4 | `MEMORY_SPEED` | 内存额定频率 > 主板标称上限 | 警告 |
| 5 | `GPU_CLEARANCE` | 显卡长度 ≤ 机箱显卡限长 | 错误 |
| 6 | `COOLER_CLEARANCE` | 风冷:散热器高度 ≤ 机箱限高;AIO:冷排尺寸 ∈ 机箱支持位 | 错误 |
| 7 | `PSU_HEADROOM` | 电源功率 / 估算负载:≥1.30 通过;[1.15,1.30) 警告;<1.15 错误 | 警告/错误 |
| 8 | `FORM_FACTOR_SUPPORT` | 主板板型 ∈ 机箱支持板型；仅支持 ITX 主板的机箱同时核对电源形态与长度 | 错误 |
| 9 | `M2_SLOT_CAPACITY` | M.2 SSD 数量合计 ≤ 主板 M.2 槽位 | 错误 |
| 10 | `GPU_POWER_CONNECTORS` | 显卡供电接口 multiset ⊆ 电源提供 | 错误 |
| 11 | `DISPLAY_OUTPUT` | CPU 无核显且无独显 → 点不亮 | 错误 |
| 12 | `COOLER_THERMAL_CAPACITY` | 散热器解热能力(W)≥ CPU TDP | 警告 |

**功耗公式(#7,冻结)**:估算负载 = CPU TDP + GPU TDP(`gpu:null` 时为 0)+ 100W 固定余项;比较用整数交叉相乘(如 `psu_w × 100 ≥ load_w × 130`),不引入浮点。上限比较类规则(#4/#5/#6/#12)等于边界即通过/不告警。

电源规格用 `form_factor=atx|sfx|sfx_l` 与 `length_mm` 表达外形；机箱用 `supported_psu_form_factors` 与 `psu_length_max_mm` 表达安装条件。历史数据缺少新增字段时仍按未知读取。当前安装校验只作用于仅支持 ITX 主板的机箱；较大机箱的电源仓、前置冷排和走线联动尚未结构化，不作推断。

## 六、数据与持久化

数据库结构以[编号迁移](../../db/migrations/)为准。PostgreSQL 存零件、字段证据、价格快照、产品会话与配置版本；修改产生子版本，不覆盖旧配置。Redis 保存会话热状态、运行事件和缓存；pgvector 提供软偏好检索。

数据采集与发布遵守[数据规则](../data/数据获取与发布规则.md)：候选、隔离、不可变 release 与运行投影分离；失败保留 last-known-good。人工价格可用，自动价格来源尚未达到激活门槛。

## 七、客户端与身份

Next.js/React 工作台通过 Go 产品 API 操作会话、配置和分享；公开页使用最小披露的只读模型。可选 Supabase Auth 由 Go BFF 隔离 Token，浏览器仅持有 HttpOnly 会话 Cookie。见[Web 客户端](Web客户端.md)、[产品 API](产品API与会话状态机.md)及[账号决策 ADR-008](技术选型.md)。
