# 评估集 v1

本版本冻结当前 30 条题目：15 条 L1 整机、10 条 L2 改单、5 条 L3 初筛。题目与期望未在此次版本化中修改；这是对已有 v1 的正式登记，不是新的运行成绩。

后续已登记 [v1.1（当前默认）](v1.1.md)，修改两条追问题的期望。以下 v1 校验/运行命令要求先恢复对应旧题目，不能直接使用已更新的当前题库。

- 机器清单：[v1.json](../../../internal/evalsuite/testdata/suites/v1.json)。冻结时间以清单 `created_at` 为准。
- 当前题库：[cases](../../../internal/evalsuite/testdata/cases/)。清单定义执行顺序，目录中新加入的题目不会自动加入 v1。
- 每题记录 ID、文件名和 SHA256；哈希按 JSON 解码后重新编码计算，忽略缩进、键顺序和编码转义差异，保留内容、数组顺序和数值表示的变化。
- 内容或期望修改后，v1 校验会失败。新增版本必须使用新清单，不覆盖 v1。历史版本题目可从历史运行的 `cases.json` 或 Git 对应版本恢复；旧清单本身不包含全文。
- 固定条件前后比较需同时核对清单哈希、代码/判卷程序、模型配置和数据快照；同名版本不等于同一内容。

## 日常操作

以下命令从仓库根运行。`check` 和 `freeze` 不读取模型凭据、不连接数据库、不调用模型。

```bash
# 检查 v1 题目与清单一致
go run ./cmd/eval -mode check -suite internal/evalsuite/testdata/suites/v1.json

# 显式运行（会调用配置的模型并读取数据库）
go run ./cmd/eval -mode run -suite internal/evalsuite/testdata/suites/v1.json -snapshot-date 2026-07-28 -seeds 3

# 修改题目并审阅后，冻结新版本；已有清单拒绝覆盖
go run ./cmd/eval -mode freeze -suite internal/evalsuite/testdata/suites/v2.json -suite-version v2

# 新版本不会自动成为默认值，使用时明确选择
go run ./cmd/eval -mode check -suite internal/evalsuite/testdata/suites/v2.json
```

`-cases` 可指定其他题库目录；`run/check` 仍以所选清单为准。版本冻结是人工审阅后的动作，不用于自动修复哈希失败。

## 运行产物

`artifacts/eval/<时间戳>-<唯一后缀>/` 避免同秒运行相互覆盖。首次模型请求之前保存：

- `cases.json`：版本清单和本次实际使用的完整题目，包括改单基线、锁定项和期望。
- `meta.json`：清单版本/哈希、重复次数、快照、三个角色的脱敏配置、启动目录的 Git commit/dirty、Go 版本和运行程序 SHA256。

结束后生成 `results.jsonl` 和 `report.md`。配置记录不含 API Key；模型链记录只是配置，不代表链内逐请求实际模型。Git 信息描述启动工作区，程序 SHA256 标识实际执行的 Runner/判卷程序；无 Git 环境时不虚构 commit。

v1 登记时的 replay 校验题目哈希、用例与重复记录完整性，从保存的题目恢复 build 断言输入；当时尚未保存 screening 原文。当前 Runner 已补齐原文留存和重判，见 v1.1；旧产物缺少证据时明确标为未复验，不追补虚假的历史版本。
