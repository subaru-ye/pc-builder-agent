# 2026-08-23 数据获取方式探查

> 目的：用真实页面、接口和开放数据验证阶段 2 取数方案，而不是根据文档猜测稳定性。
>
> 本次只产生临时候选和本文汇总，没有修改正式 `catalog`、`parts`、`prices`、数据库或 embedding，也没有调用项目配置的百炼/MiMo 模型。

## 1. 样本与方法

选择四个现有 SKU，覆盖芯片、板卡、主板和机箱：

| SKU | 样本 | 重点字段 |
|---|---|---|
| `cpu-r7-7800x3d` | AMD Ryzen 7 7800X3D | socket、TDP、核显、支持芯片组 |
| `gpu-gb-5070-windforce-sff` | Gigabyte RTX 5070 WINDFORCE OC SFF | 具体板卡长度、供电、TDP |
| `mb-msi-b650m-mortar-wifi` | MSI B650M MORTAR WIFI | socket、板型、内存、M.2 |
| `case-lianli-a3-matx` | Lian Li A3-mATX Black Mesh | 显卡限长、风冷限高、板型、冷排 |

测试方式：

1. 真实浏览器访问厂商页面和电商商品页。
2. 原始 HTTP 请求厂商页面。
3. 京东官方 API 未授权连通性请求。
4. 锁定的 `pc-part-dataset` 与离线 `dbgpu`。
5. BuildCores OpenDB 的 Git 稀疏克隆和精确型号匹配。
6. 对厂商页面做带 schema 的模型辅助结构化抽取。
7. 搜索引擎/AI 摘要直接寻找商品价格。

## 2. 实测结果总表

| 方式 | 实测结果 | 稳定性判断 | 适合用途 |
|---|---|---|---|
| 浏览器直开厂商页 | 技嘉和 AMD 页面在 30 秒内未完成；页面脚本重 | 低，不适合定时批量 | 人工复核兜底 |
| 浏览器搜索价格 | Bing 可返回约 3299 元的 AI 摘要和京东链接，但无店铺、库存、优惠条件和证据 | 很低 | 发现候选链接，不得入价 |
| 浏览器直开京东商品 | 精确商品 URL 跳转登录页，匿名状态拿不到商品价格 | 低 | 人工登录后的临时核对 |
| 原始 HTTP 厂商页 | 技嘉返回 403；AMD 15 秒无响应；Lian Li 返回 200，但目标规格不在首段静态 HTML | 低且厂商差异大 | 少量厂商专用适配器 |
| 京东官方 API | 网关可达，但无 appkey 返回 `10001`；官方文档确认需要应用、签名和权限 | 获权后预期高 | 核心池价格首选 |
| `pc-part-dataset` | 锁定 CPU JSONL 下载成功，224,556 bytes / 8.65 秒；远端 main 仍等于当前锁定 commit | 技术稳定但数据陈旧 | 现有候选基线 |
| `dbgpu` 离线包 | RTX 5070 返回 TDP 250W、参考板长 245mm、16-pin | 高，但仅芯片/公版层 | GPU 芯片字段兜底 |
| BuildCores OpenDB | 成功获得 33,876 个 JSON，四个样本均有精确或近精确匹配 | 中高，需版本锁和质量抽检 | 新 SKU 发现、结构化候选 |
| 模型辅助厂商页抽取 | AMD、Lian Li 关键字段正确；技嘉样本发生字段语义误映射 | 获取能力高，事实可靠性不足 | 候选抽取，必须审核 |

## 3. 浏览器与搜索引擎

### 3.1 厂商规格页

真实浏览器访问以下页面：

- [Gigabyte RTX 5070 WINDFORCE OC SFF](https://www.gigabyte.com/Graphics-Card/GV-N5070WF3OC-12GD/sp)
- [AMD Ryzen 7 7800X3D](https://www.amd.com/en/products/processors/desktops/ryzen/7000-series/amd-ryzen-7-7800x3d.html)

两次均未在 30 秒内完成导航。页面最终可被专业抓取服务解析，但浏览器首屏依赖脚本、地区节点和资源加载，不能作为每周批处理的主要入口。

结论：浏览器适合人工打开一个已知 URL 做最终核对，不适合作为 80–120 个核心 SKU 的无人值守更新器。

### 3.2 电商价格

浏览器搜索“京东 Ryzen 7 7800X3D 价格”得到 AI 摘要“3299 元左右”，同时发现精确京东商品链接。直接访问商品链接后进入京东登录页，没有得到可验证价格。

现有项目快照中该 CPU 在 2026-07-28 的价格是 2599 元。搜索摘要与旧快照相差约 27%，但摘要没有说明它是盒装/OEM、哪个店铺、是否有货、是否包含优惠或抓取时间，因此不能判断哪一个值正确。

结论：搜索引擎和大模型搜索适合发现商品 URL，不允许生成正式价格观察值。

## 4. 官方 API

京东官方文档列出：

- `jd.union.open.goods.query`：按 SKU/关键词查询商品及优惠券。
- `jd.union.open.goods.promotiongoodsinfo.query`：按 SKU 查询名称、价格、物流、自营等信息。

见[京东联盟官方接入说明](https://jos.jd.com/jdunion)。

对 JOS 网关发送不含凭据的只读请求，网关 HTTP 可达并返回：

```json
{
  "error_response": {
    "code": "10001",
    "zh_desc": "入参异常(appkey为空或请求体大小超过3M).[NG.beta]"
  }
}
```

这证明接口存在且必须经过 appkey、签名和权限流程；它不能在当前仓库中直接匿名调用。没有实际权限前，不能把京东 API 写成阶段 2 已可用能力。

结论：**获得权限后，官方 API 是价格更新最值得优先投入的方法**。未获得权限期间继续使用人工 CSV，不用网页爬虫冒充稳定接口。

## 5. 开放结构化数据

### 5.1 `pc-part-dataset`

当前锁定和远端 main 都是：

```text
c52a04ca9465c83997ed335f7767b09a2005dd26
```

这说明现有版本可复现，但上游没有继续更新，不能用于发现 2025 年之后持续新增的型号。它仍适合作为当前 160 个 SKU 的稳定基线。

### 5.2 `dbgpu`

离线查询 `GeForce RTX 5070` 得到：

```text
tdp_w=250
board_length_mm=245
power_connectors=1x 16-pin
```

具体技嘉板卡官方长度为 282mm。TDP 和接口可作芯片级候选，但公版 245mm 不能覆盖 AIC 板卡 282mm。这与现有“具体产品字段优先于芯片层”规则一致。

### 5.3 BuildCores OpenDB

探查锁定到 commit：

```text
136a77aec16a30ba81a7cc6b448a8bace9a25359
```

提交时间为 2026-08-17，共发现 33,876 个 JSON 和 31 个 schema 文件。样本结果：

- 7800X3D：区分盒装和 OEM，包含 part number、AM5、120W、核显和厂商 URL。
- 技嘉 RTX 5070：精确 part number `GV-N5070WF3OC-12GD`，包含 282mm、250W、12V-2x6 和厂商 URL。
- MSI B650M MORTAR：包含 AM5、Micro ATX、DDR5、两个 M.2 和厂商 URL。
- Lian Li A3：包含具体颜色/侧板变体、415mm、165mm 和厂商 URL。

同时发现质量问题：一个 Black Mesh A3 记录把 `has_transparent_side_panel` 标为 true，部分尺寸/电源字段在不同变体间完整度不一致。仓库自身也声明不提供价格。

结论：BuildCores 是目前最适合新增的“候选发现源”，但不能替代厂商证据，也不能直接全量覆盖现有 catalog。建议每月检查锁定 commit，只处理与当前目录有关的增量文件；不必每周重新拉 3 万多个 JSON。

## 6. 模型辅助结构化抽取

对三个官方页面使用固定 JSON schema，并要求缺失字段返回 null：

### 6.1 成功样本

- AMD 7800X3D：正确提取 AM5、120W、AMD Radeon Graphics；页面未明确给出的支持芯片组返回空数组。
- Lian Li A3：正确提取 415mm、165mm、M-ATX/ITX 和不同位置的冷排规格。

### 6.2 失败样本

技嘉页面明确写出：

```text
Card size: L=282 W=110 H=50 mm
Recommended PSU: 750W
Power Connectors: 16 Pin
```

页面没有显式板卡 TDP。模型虽然给出了合法 JSON，却把 `Recommended PSU: 750W` 填入了 `board_power_w`。这是语法校验无法发现的语义错误。

结论：模型抽取必须保留逐字段证据，并增加跨字段语义校验，例如：

- `Recommended PSU` 不得映射为 `tdp_w/board_power_w`。
- `Card size L/W/H` 必须按字段名取轴，不能把任意尺寸数字当长度。
- 页面未出现目标标签时必须为 null，不能使用邻近数字补位。

本次没有调用项目配置的百炼/MiMo 模型：当前 Agent 模型本身没有浏览器或搜索工具，直接询问只会产生无法证明的新事实并消耗额度。Bing AI 摘要和带 schema 的页面抽取已经覆盖了“模型直接找”和“模型基于页面抽取”两种风险。

## 7. 发现的现有数据候选问题

本次不直接修正式数据，但产生一个需要后续审核的候选：

- 当前 `cpu-r7-7800x3d.supported_chipsets` 缺少 `B840`。
- AMD 当前产品页和[AM5 芯片组官方页](https://www.amd.com/en/products/processors/chipsets/am5.html)均把 Ryzen 7000 与 B840 纳入 AM5 兼容范围。
- 修复前仍需确认 canonical 规则、全部 AM5 CPU 是否统一更新，以及加入 B840 会不会扩大阶段 3 的平台范围。

其余三个样本的项目关键字段与官方页面/开放数据候选一致，但现有 `source_meta` 仍缺字段级 URL 和证据时间。

## 8. 推荐方案与排序

### 8.1 规格数据

1. **BuildCores / 现有公开数据集按 commit 拉取**：用于发现候选和初始结构化字段。
2. **厂商官方页面或说明书**：只核验新增/变化 SKU 的关键字段。
3. **确定性厂商适配器**：对页面结构稳定、数量较多的厂商逐个建设。
4. **模型辅助抽取**：适配器缺失时生成候选，强制逐字段证据和人工审核。
5. **真实浏览器**：只处理抓取失败、登录或视觉歧义的少量例外。

### 8.2 价格数据

1. **京东联盟官方 API**：获得权限后作为核心池主要来源。
2. **人工/浏览器核验 CSV**：API 未获权或单个商品缺失时兜底。
3. **搜索引擎或模型价格**：只能发现链接，禁止进入价格快照。

### 8.3 调度

- 每周：只刷新 `active_core` 价格候选并生成 Diff。
- 每月：检查 BuildCores 和现有数据集的新 commit，提取与目录相关的增量。
- 新品/冲突时：抓厂商页，模型辅助抽取，人工批准。
- 发布：永远显式执行，不由定时任务自动触发。

最终选择不是某一种万能方式，而是：**开放结构化数据负责发现，厂商页面负责证据，官方 API 负责价格，模型负责候选抽取，浏览器负责少量异常，人工负责发布。**
