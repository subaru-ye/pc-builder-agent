# 网页读取与补库策略

## 当前读取策略（2026-09-14）

在线业务暂时仅查询装机技术资料：优先厂商官网规格、兼容性/BIOS支持、安装排障指南、配件知识和性能资料，不用于查询具体价格、优惠、库存或购买信息。Builder 在同一次规划调用中遵守该用途说明，不增加分类模型或价格关键词拦截；服务端新注册外部候选时清除网页报价及其来源映射，防止偶然读到的标价进入配置总价。本地价格快照继续使用并保留原观察日期，缺价明确未知，仍可讨论和保存方案；旧正式版本与历史快照保持不变。买手补价格属于独立、人工复核的数据维护流程，不是客户端实时联网查价。Firecrawl 目前仅完成评估，尚未替换业务搜索/读取供应商。

`search_web` 继续使用 SerpAPI 百度搜索；`read_page` 默认 `method=auto`，先普通 HTTP，只有可识别的动态空壳才自动升级到 Crawl4AI。模型也可明确选择 `http` 或 `browser`，例如已有静态正文但缺少动态表格。HTTP 非成功状态、验证码、登录、Cookie 同意墙、限流、网络故障不自动换浏览器重试；收到访问限制后应换公开来源，不尝试绕过。Screening 不新增联网或总结调用，Builder 自主决定是否检索和读取，不强制每次规划联网。

Docker 仍使用固定的 `unclecode/crawl4ai:0.9.3` 镜像，但默认入口改为仓库内 `deploy/crawl4ai/reader.py`，通过 HTTP `/read` 调用官方 Python API；不再使用上游通用 `/crawl` 端点。原因是原评估证明同步 `/crawl` 不经过声明的后台队列，客户端取消也不保证回收远端浏览器。新的小接口专门约束一次页面读取，不是另一套搜索服务。

- 服务端点和 Bearer 凭据来自环境，不接受模型指定；宿主只暴露 `127.0.0.1:11235`。
- 请求仅为 `POST /read {"url":"https://..."}`，不接受额外字段。浏览器配置在服务端直接构造，固定 headless/text_mode=true，不开放脚本、深爬、登录凭据或 LLM 提取配置。不向容器传入模型或 SerpAPI 密钥。
- 浏览器等待 DOM 加载及短暂动态渲染，使用清理后的原始 Markdown，保留短参数和表格，不用激进的 fit Markdown 作为唯一证据。
- `Evidence.text` 保存完整的有界正文，HTTP 原始响应及解码后文本各限 2 MiB，浏览器 Markdown 限 2 MiB；不保存全部 HTML、图片或子资源。超限明确失败，不悄悄截断成完整证据。新增 final_url、reader、http_status、read_bytes，旧记录可缺失，不批量改写旧证据。网页获取时间不等于价格观察时间。
- HTTP 按响应头或 HTML 声明解码字符集（包括 GBK），保留段落与表格单元边界；浏览器记录主框架实际最后响应状态和 URL，307 后的已观测 200 可正常读取，未知最终状态不能假定成功。
- 每次模型视图最多 16000 个 Unicode 字符。`read_page`、`read_evidence` 支持 query/offset/limit，返回 offset、next_offset、total_chars、truncated 和 query_matched；按 query 定位相关行附近，未命中明确反馈。完整正文保留在同一方案证据快照中；跨轮恢复后也可 `read_evidence` 续读。长文章多个资料区可能需要不同 query 或顺序分页，不能把一次窗口当作全文。
- 每个 read_page 仍计一次页面工具调用；自动升级最多实际读取两次，共用 55 秒截止时间，read_attempts 分别记录方式、耗时、响应体字节、状态和结果（含失败）。8 次模型、24 次工具、3 次搜索、6 次读页上限不变；read_evidence 只占工具额度，不占读页或搜索额度。浏览器子资源不等于搜索次数，响应体字节也不等于外网流量。
- 抓取缓存显式 bypass，避免缓存旧报价冒充新读取。复用同轮已有证据用 read_evidence；跨运行按资料类型设置缓存期限留待后续。
- 服务整体期限 45 秒，包含排队、子进程启动和页面读取；请求体最多 8 KiB/2 秒。实际 `/read` 路径最多 2 个执行、8 个等待，保留每分钟 60 次准入上限，超出返回 429；不是依靠上游作业队列配置。容器仍为 4 GiB/2 CPU，客户端响应限制 8 MiB。
- 每次浏览器读取独占进程组和临时目录，不复用 Cookie 或浏览器上下文。正常完成、断开连接、超时及退出都会回收进程组，再释放容量；Compose 使用 init 回收子进程。代价是每次付出浏览器启动成本。`/health` 返回协议 `pc-page-reader/1`；受 Bearer 保护的 `/metrics` 给出在途数、活动数及累计完成/取消/超时数，不含网址或正文。completed 只表示任务返回结果，不表示证据质量通过。
- Go 拒绝私网和非 HTTPS 目标；0.9.3 服务的出口代理对浏览器连接固定解析地址，校验重定向/子资源。不得启用 ALLOW_INTERNAL_URLS / ALLOW_INSECURE_TLS，Bearer 客户端不跟随服务跳转。

启动：在仓库根目录运行 `python scripts/start-crawl4ai.py`。脚本只在 `.env` 缺少或为空时生成 URL 和本地 Token，然后执行 Compose；已有凭据保留且不输出。随后重新构建并重启 buildsvc；旧二进制的 `/crawl` 协议不能混用新服务。检查 `http://127.0.0.1:11235/health` 的协议字段。停止只用 `docker compose stop crawl4ai`。清空 CRAWL4AI_URL 并重启 buildsvc 可只使用 HTTP。历史 `config.yml` 仅留作原 A/B 复现，已不挂载到当前服务。

服务是网络查询辅助依赖，不加入整个产品 API 的硬性就绪条件；容器不可用不影响需求收集、历史读取或纯本地规划。

官方参考：[快速入门](https://docs.crawl4ai.com/core/quickstart/)、[0.9.3 迁移说明](https://github.com/unclecode/crawl4ai/blob/v0.9.3/deploy/docker/MIGRATION.md)。部分自托管文档仍有旧版示例，接口以固定标签及实际容器验证为准。

## v3.1 批次判断

现有批次是既有 160 SKU 的价格更新，不是型号发现或规格补全。已归档 102 accept、58 carry 和 708 条复核学习记录，见[批次说明](../../scripts/data/price-batches/2026-09-08/README.md)。本轮不重采、不导入产品库、不修改该历史决策表。

按最终 CSV 统计：CPU 18 更新/2 沿用、GPU 8/12、主板 15/5、内存 13/7、SSD 10/10、电源 14/6、机箱 11/9、散热 13/7。价格补采优先考虑 GPU 和 SSD；脚本中的早期分组注释不能代替最终快照统计。

保留精确型号/变体判定、无法唯一匹配显式失败、原始记录和决策可回放的做法。买手是聚合快照来源，`aggregator_secondary` 及学习/评测用途应继续保留；通过 detail 对价只证明同一聚合渠道的一致性，不能升级为平台授权、现货或最终成交证明。carry 的旧观察时间不得随新批次更新。

价格带和家族梯度适合作为异常提示，不宜作为价格真实性的唯一判据：真实降价可能越过旧价带，不同商家促销也可能改变梯度。异常行保留并单独复核，不能直接改成 accept。京东“已选变体”经验也只适用于对应返回行，不能泛化为所有京东聚合记录可信。

## 建议的后续补库顺序（尚未执行）

1. 从真实方案缺项、重复搜索及常用升级路径形成小批次清单；不再只从固定 160 SKU 生成搜索词。优先 CPU/主板支持与 BIOS、显卡准确变体、电源接口和机箱/散热空间。
2. 新型号先建公共产品候选身份（品牌、准确型号、后缀、容量/条数、盒装/散片等），再通过适用厂商资料补字段级规格和支持关系。Crawl4AI 负责读资料，不能把型号相近当成同件，也不能补造未知规格。
3. 买手继续补价格观察、店铺、goodsId 和链接。用 source + goodsId + 明确变体 + 原始行哈希稳定关联，needle 保留为可读核对依据。价格、型号身份和规格证据分开保存。
4. 日常 Agent 查到的会话候选仍留在会话；重复出现且证据足够的公共商品事实进入现有 review/quarantine/release 流程，经复核回流，不直接发布模型推断，不包含用户私人需求。
5. 区分学习/评测快照、产品参考报价和已核验商家报价。发布前明确目标库、快照日期、每条观察时间及 source_type，预览 Diff，再按现有事务导入；历史配置引用的旧快照保持不变。

买手与 Crawl4AI 可以共同补库，但当前只完成对话 read_page 的 Docker 接入，未替换或启动后台采集脚本。衡量扩库效果采用关键字段覆盖率、价格新鲜度、误绑率、常见需求本地完成率和重复检索次数，不能仅以 SKU 总量验收。
