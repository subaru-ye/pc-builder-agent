## 过程发现（不阻塞，登记待处理）

1. **Auth 环境坑**：`.env.example` 自带空 `SUPABASE_JWT_SECRET=`/`AUTH_SESSION_SECRET=` 行，
   `authsetup` 追加非空值后 compose 仍读到旧空值，auth 容器 crash-loop（jwk key 为空）；
   需删除空行并 `docker compose --profile auth up -d --force-recreate auth`。建议后续让
   authsetup 顺带清理空重复行（独立小改动，未并入本分支）。
2. `AUTH_ENABLED` 默认 false，`cmd/api` 需显式 `AUTH_ENABLED=true` 才启用账号（文档已有，容易漏）。
3. 登录后 `/api/v1/auth/me` 的 `claimed_session_count` 返回 0，而实际认领了 1 个会话（库内核实
   认领关系正确）；疑似该字段只在注册/登录响应填充，auth/me 语义待查——不影响功能。
4. 新会话"可选偏好"分组在全部未指定时折叠，静音等行需先展开（既有 UI 规则，走查路径需注意）。
5. 走查工具限制：IAB 内 Playwright 原生 click 全部超时，统一改用页面内 `el.click()`；不影响产品。

## 多 owner 冲突的构造方式（可复现）

同一账号拥有两个 owner 的唯一自然路径：两个匿名身份分别产生数据后先后被同一账号认领。
本走查用 注册（认领 A）→ 登出 → 新匿名身份 C 保存 → 登录（认领 C）实现；
冲突以"静音：安静（A）vs 静音：常规（C）"呈现，用户手选其一，服务端不代选（与单测一致）。
